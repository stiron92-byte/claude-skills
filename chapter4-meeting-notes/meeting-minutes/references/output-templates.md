# 회의록 출력 템플릿 모음

역할 × 용도 조합에 따라 아래 템플릿을 기본 구조로 사용한다.
각 템플릿은 상황에 맞게 섹션을 추가하거나 축소할 수 있다.

---

## 1. 팀 공유용 (공통 템플릿)

분량: 원문의 20~30%. 요약 중심, 액션 아이템 강조, 불필요한 잡담 제거.

```markdown
# 📋 {회의 제목}

- **일시**: {날짜}
- **참석자**: {이름 목록}

## 핵심 요약

- (3~5줄 요약)

## 결정 사항

1. ...
2. ...

## 액션 아이템

| 담당자 | 할 일 | 기한 |
|--------|-------|------|
| ... | ... | ... |

## 다음 회의

- 일정: ...
- 안건: ...
```

### 역할별 팀 공유용 변형

- **PM**: 액션 아이템 표에 "의존성" 열 추가, 마일스톤 진행률 포함
- **기획자**: "요구사항 변경 사항" 섹션 추가
- **영업**: "고객 요청 사항" 섹션 추가, 후속 조치 기한 강조
- **인사**: "정책 변경 사항" 섹션 추가
- **개발자**: "기술 결정 사항" 섹션 추가, 이슈/버그 목록 포함
- **디자이너**: "디자인 피드백 요약" 섹션 추가, 리비전 항목 목록

---

## 2. 상위 보고용 템플릿

분량: 원문의 30~40%. 배경 설명 추가, 결론 먼저, 보고서 톤.

```markdown
# {회의 제목} 회의 보고서

**보고일**: {날짜}  |  **작성자**: {역할}

---

## 1. 배경 및 목적

(이 회의가 왜 열렸는지, 어떤 맥락에서 논의가 필요했는지)

## 2. 주요 논의 사항

### 2.1 {안건 1}

- **논의 내용**: (요약)
- **결정 사항**: (확정된 내용)
- **미결 사항**: (있는 경우)

### 2.2 {안건 2}

- **논의 내용**: (요약)
- **결정 사항**: (확정된 내용)

## 3. 결론 및 합의 사항

(최종 결론을 간결하게 정리)

## 4. 후속 조치 (Action Items)

| # | 항목 | 담당 | 기한 | 비고 |
|---|------|------|------|------|
| 1 | ... | ... | ... | ... |

## 5. 다음 단계

(향후 계획, 다음 회의 일정, 에스컬레이션 필요 사항 등)
```

### 역할별 상위 보고용 변형

- **PM**: "리스크 및 이슈" 섹션 추가, 프로젝트 타임라인 현황 포함
- **기획자**: "사용자 피드백 반영 현황" 섹션 추가
- **영업**: "매출/계약 영향" 섹션 추가, 금액/수치 강조
- **인사**: "조직 영향도" 섹션 추가, 채용/평가 일정 포함
- **개발자**: "기술 아키텍처 결정" 섹션 추가, 기술 부채 현황 포함
- **디자이너**: "디자인 방향성 결정" 섹션 추가, 브랜딩 가이드 반영 여부 포함

---

## 3. 개인 기록용 템플릿

분량: 원문의 60~80%. 상세 논의 내용 보존, 발언자별 정리, 맥락 유지.

```markdown
# 🗒️ {회의 제목} — 상세 기록

**일시**: {날짜}  |  **참석**: {이름 목록}

---

## 안건별 상세 논의

### 안건 1: {주제}

- **{발언자 A}**: (발언 내용 상세)
- **{발언자 B}**: (발언 내용 상세)
- **{발언자 C}**: (발언 내용 상세)
- → **결론**: ...

### 안건 2: {주제}

- **{발언자 A}**: (발언 내용 상세)
- **{발언자 B}**: (발언 내용 상세)
- → **결론**: ...

(안건별 반복)

---

## 결정 사항 종합

1. ...
2. ...

## 액션 아이템 (나의 할 일)

- [ ] {할 일 1} — 기한: {날짜}
- [ ] {할 일 2} — 기한: {날짜}

## 나의 메모 / 추가 생각

- (사용자가 나중에 직접 추가할 공간)
```

### 역할별 개인 기록용 변형

- **PM**: 각 안건에 "일정 영향" 메모 추가, 리스크 태깅
- **기획자**: 각 안건에 "요구사항 변경 여부" 태깅
- **영업**: 고객 발언 별도 하이라이트, 가격/조건 관련 내용 강조
- **인사**: 민감 정보 주의 표시, 정책 변경 이력 추적
- **개발자**: 코드/기술 관련 발언 코드블록 처리, TODO 태깅
- **디자이너**: 디자인 피드백 별도 섹션, 참조 이미지/링크 공간

---

## 4. 이메일 공유용 템플릿

분량: 원문의 15~20%. 인사말 포함, 본문 3~5문단, 액션 아이템 하단 배치.

```markdown
안녕하세요,

{날짜} 진행된 {회의 제목} 회의 내용을 공유드립니다.

**주요 논의 사항:**
- {안건 1}: {한 줄 요약}
- {안건 2}: {한 줄 요약}

**주요 결정 사항:**
- {결정 1}
- {결정 2}

**후속 조치:**
- {담당자}: {할 일} (기한: {날짜})
- {담당자}: {할 일} (기한: {날짜})

자세한 사항은 회의에서 논의된 내용을 참고 부탁드립니다.
궁금하신 점 있으시면 말씀해 주세요.

감사합니다.
```

### 역할별 이메일 변형

- **PM**: "프로젝트 일정 업데이트" 섹션 추가
- **기획자**: "요구사항 변경 알림" 톤으로 작성
- **영업**: "고객 후속 조치" 중심, 긴급도 표시
- **인사**: 공식적 톤, 정책 관련 내용은 별도 첨부 안내
- **개발자**: "기술 결정 공유" 톤, 관련 문서/이슈 링크 포함
- **디자이너**: "디자인 리뷰 결과" 톤, 다음 리비전 일정 포함

---

## 5. 노션 복붙 시 주의사항

노션에 붙여넣을 때 잘 인식되는 마크다운 문법:
- `#`, `##`, `###` 헤딩 → 정상 인식
- `- `, `1. ` 목록 → 정상 인식
- `- [ ]` 체크박스 → 정상 인식 (할 일 블록으로 변환)
- `| 표 |` 마크다운 테이블 → 정상 인식
- `**굵게**`, `*기울임*` → 정상 인식
- `> 인용` → 정상 인식
- `---` 구분선 → 정상 인식

노션에서 잘 안 되는 것:
- HTML 태그 → 사용하지 않는다
- 토글/콜아웃 등 노션 전용 블록 → 일반 텍스트로 대체
- 중첩 테이블 → 단순화하여 표현
