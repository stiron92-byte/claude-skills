# 회의록 자동 정리 스킬

회의 녹음 파일(음성) 또는 회의 텍스트를 입력받아, 사용자의 역할과 용도에 최적화된 회의록을 자동 생성하는 통합 스킬이다.

> 📁 **샘플 회의 녹음**: `example/` 폴더에 테스트용 회의 녹음 3개(한국어 2 · 영어 1)와 설명(`README.md`)이 들어 있습니다. 바로 시험해보려면 이 파일을 업로드하고 "정리해줘"라고 요청하세요.

---

## 1. 전체 동작 흐름

```
입력 감지 → 사전 질의(역할/용도/형식) → [음성이면 STT 변환] → 회의록 생성 → 출력
```

---

## 2. 입력 타입 자동 감지

스킬이 트리거되면, 먼저 입력 타입을 판별한다:

- **음성 파일 감지**: `/mnt/user-data/uploads/` 에 `.mp3`, `.wav`, `.m4a`, `.webm`, `.ogg` 확장자 파일이 있으면 → 음성 입력 경로
- **텍스트 감지**: 사용자 메시지에 회의 내용 텍스트가 직접 포함되어 있으면 → 텍스트 입력 경로
- **판별 불가 시**: 사용자에게 "음성 파일을 업로드하시겠어요, 아니면 텍스트를 붙여넣으시겠어요?" 라고 질문

---

## 3. 사전 질의 (스킬 시작 시 반드시 수행)

입력 타입이 확인되면, 회의록 작성 전에 **반드시 아래 3가지를 사용자에게 질문**한다. 이 질문은 출력 품질을 크게 좌우하므로 절대 건너뛰지 않는다. 사용자가 이전 대화에서 이미 밝힌 경우는 확인 질문으로 대체할 수 있다.

### 질문 1 — 사용자 역할 (단일 선택)

> 어떤 역할로 이 회의록을 작성하시나요?

선택지:
1. PM / 프로젝트 매니저
2. 기획자 / 전략
3. 영업 / 세일즈
4. 인사 / HR
5. 개발자 / 엔지니어
6. 디자이너
7. 기타 (직접 입력)

### 질문 2 — 회의록 용도 (단일 선택)

> 이 회의록을 어떤 용도로 사용하시나요?

선택지:
1. 팀 공유용 — 간결한 요약 + 액션 아이템 중심
2. 상위 보고용 — 보고서 형태, 배경·결론·다음 단계 포함
3. 개인 기록용 — 상세 논의 내용 전부 포함
4. 이메일 공유용 — 본문에 바로 붙여넣을 수 있는 형태

### 질문 3 — 출력 형식 (단일 선택)

> 어떤 형식으로 출력할까요?

선택지:
1. 마크다운 파일 (.md)
2. 워드 문서 (.docx)
3. 채팅에서 바로 확인 (텍스트 출력)
4. 노션 복붙용 마크다운

---

## 4. 음성 입력 경로 — STT 처리

음성 파일이 감지된 경우, 아래 순서로 처리한다.

### 4.1 파일 크기 제한 안내

음성 파일 감지 즉시, 파일 크기를 확인하고 아래 기준으로 안내한다:

| 파일 크기 | 예상 녹음 시간 | 처리 가능 여부 | 예상 소요 시간 |
|-----------|---------------|--------------|--------------|
| ~10MB 이하 | ~10분 이내 | ✅ 원활 | 1~2분 |
| 10~25MB | ~10~30분 | ✅ 가능 | 2~5분 |
| 25~50MB | ~30분~1시간 | ⚠️ 가능하나 느림 | 5~10분 |
| 50MB 초과 | 1시간 이상 | ❌ 권장하지 않음 | 시간 초과 위험 |

- **50MB 초과 파일**: "이 파일은 약 {X}MB로, 컨테이너 환경에서 처리하기에 너무 큽니다. 아래 방법을 추천합니다: (1) 노션 녹음 기능으로 텍스트 변환 후 텍스트를 붙여넣기, (2) Clova Note 등 외부 STT 서비스로 먼저 텍스트 변환, (3) 녹음 파일을 30분 단위로 분할 후 업로드" 라고 안내한다.
- **처리 가능한 파일**: "약 {예상 시간} 정도 소요됩니다. 변환을 시작할까요?" 라고 확인 후 진행한다.

### 4.2 STT 변환 실행

```bash
# 1. faster-whisper 설치 (미설치 시)
pip install faster-whisper --break-system-packages

# 2. 트랜스크립션 실행
python /mnt/skills/user/meeting-minutes/scripts/transcribe.py \
  --input "/mnt/user-data/uploads/{파일명}" \
  --output "/home/claude/transcript.txt" \
  --language "ko"
```

- 기본 모델: `base` (빠른 속도 우선, ~150MB)
- 한국어가 주 언어이고 정확도가 더 필요하면 `--model small` (~500MB)로 전환 가능
- 진행 중 사용자에게 "음성을 텍스트로 변환하고 있습니다... 🎙️→📝" 와 같은 진행 메시지를 표시한다.

### 4.3 STT 결과 검증

변환 완료 후:
- 변환된 텍스트의 처음 200자를 사용자에게 보여주며 "변환 결과가 괜찮은지 확인해주세요" 라고 요청한다.
- 문제가 있으면 `small` 모델로 재시도하거나, 텍스트 직접 입력을 안내한다.

---

## 5. 텍스트 입력 경로

텍스트가 직접 입력된 경우:
- STT 단계를 완전히 건너뛰고 바로 사전 질의(섹션 3) → 회의록 생성(섹션 6)으로 진행한다.
- "텍스트를 직접 입력하셨네요. 바로 정리를 시작하겠습니다!" 라고 안내한다.
- 이 경로는 노션 녹음 → 텍스트 변환 결과를 복사해 온 경우도 포함한다.

---

## 6. 회의록 생성 — 역할 × 용도 매트릭스

회의록 내용을 생성할 때, `/mnt/skills/user/meeting-minutes/references/output-templates.md`를 반드시 참조하여 역할과 용도 조합에 맞는 구조를 적용한다.

### 6.1 공통 추출 항목 (모든 조합에 포함)

1. **회의 기본 정보**: 회의 제목(추정), 날짜, 참석자(언급된 이름 기반)
2. **안건 목록**: 논의된 주제를 번호로 정리
3. **핵심 결정 사항**: 확정된 내용
4. **액션 아이템**: 담당자 + 기한 + 할 일 (표 형태)
5. **다음 회의 예정**: 언급된 경우

### 6.2 용도별 차이

| 용도 | 분량 기준 | 특징 |
|------|----------|------|
| 팀 공유용 | 원문의 20~30% | 요약 중심, 액션 아이템 강조, 불필요한 잡담 제거 |
| 상위 보고용 | 원문의 30~40% | 배경 설명 추가, 결론 먼저, "다음 단계" 섹션 필수, 보고서 톤 |
| 개인 기록용 | 원문의 60~80% | 상세 논의 내용 보존, 발언자별 정리, 맥락 유지 |
| 이메일 공유용 | 원문의 15~20% | 인사말 포함, 본문 3~5문단, 액션 아이템 하단 배치 |

### 6.3 역할별 강조점

| 역할 | 회의록에서 특히 강조할 것 |
|------|----------------------|
| PM / 프로젝트 매니저 | 일정, 마일스톤, 리스크, 의존성, 담당자 배정 |
| 기획자 / 전략 | 요구사항 변경, 사용자 피드백, 우선순위 결정 |
| 영업 / 세일즈 | 고객 요청, 가격/계약 관련, 후속 조치, 기한 |
| 인사 / HR | 채용 결정, 평가 관련, 조직 변경, 정책 사항 |
| 개발자 / 엔지니어 | 기술 결정, 아키텍처 논의, 버그/이슈, 기술 부채 |
| 디자이너 | 디자인 피드백, UX 결정, 브랜딩 관련, 리비전 요청 |

## 7. 출력 형식별 처리

### 7.1 마크다운 (.md)

- `/home/claude/meeting-minutes-{YYYYMMDD}.md` 에 파일을 생성한다.
- `/mnt/user-data/outputs/` 디렉토리에 복사한다.
- `present_files`로 사용자에게 전달한다.

### 7.2 워드 문서 (.docx)

- **반드시** `/mnt/skills/public/docx/SKILL.md` 를 먼저 읽고 해당 가이드의 문서 생성 패턴을 따른다.
- 표지, 목차는 상위 보고용일 때만 포함한다.
- `/mnt/user-data/outputs/` 에 복사 후 `present_files`로 전달한다.

### 7.3 채팅 내 텍스트 출력

- 파일을 생성하지 않고 채팅 메시지로 직접 출력한다.
- 마크다운 서식을 사용하되 과도한 포맷팅은 지양한다.

### 7.4 노션 복붙용 마크다운

- 노션에서 잘 인식되는 마크다운 문법만 사용한다.
- 토글(접기), 콜아웃 등 노션 전용 블록은 텍스트로 대체한다.
- 체크박스 `- [ ]` 형태로 액션 아이템을 작성한다.
- 채팅에 출력하면서 "이 내용을 복사해서 노션에 붙여넣으세요" 라고 안내한다.

## 8. 완료 후 안내

회의록 출력이 완료되면 아래 메시지를 자연스럽게 전달한다:

> 💡 **이 스킬은 회의록 외에도 활용할 수 있어요:**
> 강의 노트 정리, 인터뷰 기록 정리, 상담/코칭 기록 정리에도 동일하게 사용할 수 있습니다.
> 다음에 녹음 파일이나 텍스트를 주시면서 "정리해줘" 라고 말씀하시면 됩니다.

---

## 9. 중요 제약 사항

1. **디스크 용량**: 컨테이너 환경이므로 faster-whisper 모델 다운로드(base ~150MB, small ~500MB)와 음성 파일이 동시에 존재할 수 있는 공간을 고려한다. 처리 완료 후 임시 파일 정리를 반드시 수행한다.

2. **처리 시간 안내**: 음성 파일 처리 시 반드시 예상 소요 시간을 사전에 안내하고, 오래 걸리는 경우 진행 상황을 주기적으로 알려준다.

3. **대용량 파일 가이드**: 50MB 초과 파일은 처리를 거부하고 대안(노션 STT, 외부 STT 서비스, 파일 분할)을 안내한다.

4. **언어 처리**: 한국어와 영어를 지원한다. 회의 내에서 한국어/영어가 혼용되는 경우도 처리할 수 있어야 한다. faster-whisper의 language 파라미터를 적절히 설정한다.

5. **텍스트 입력 시 빠른 처리**: 이미 텍스트가 있는 경우 STT 단계를 완전히 건너뛰어 빠르게 결과를 제공한다.

6. **사전 질의 필수**: 역할, 용도, 출력 형식 3가지 질문은 반드시 스킬 시작 시 수행한다.

7. **워드 문서 생성 시**: 반드시 `/mnt/skills/public/docx/SKILL.md` 를 먼저 읽고 해당 가이드의 문서 생성 패턴을 따른다.
