# 실습 4: 한글(HWPX) 문서 — 양식은 그대로, 내용만 바꾸기

이번 실습에서는 개발자들 사이에서 까다롭기로 유명한 **한글 파일(.hwpx)**을 다루어 보겠습니다.

관공서나 공공기관에서 근무하시는 분이라면, 결재문서·공문·기안서 등 한글 파일을 매일같이 사용하실 텐데요. 이런 문서들은 기관 로고, 결재란, 수발신 테이블 등 정해진 양식 위에 내용만 바꿔 가며 작성하는 경우가 대부분입니다.

이번 실습에서는 실제 서울시 산하기관에서 사용하는 결재문서 양식을 가져와서, AI에게 "이 양식 그대로 두고 내용만 불꽃축제 보고서로 바꿔줘"라고 말하는 것만으로 문서를 완성해 보겠습니다. 코드를 작성하거나 터미널을 열 필요가 전혀 없습니다.


## 왜 한글 파일이 까다로울까?

한글 파일이 어렵다는 이야기는 개발자들 사이에서 유명합니다. 그 이유는 HWPX의 구조에 있습니다.

HWPX는 겉보기에는 하나의 파일이지만, 실제로는 ZIP 압축 파일 안에 여러 개의 XML과 이미지가 들어 있는 복합 문서입니다. 본문 텍스트, 글꼴 정보, 기관 로고, 직인 이미지가 각각 별도의 파일로 나뉘어 들어 있습니다.

문제는 본문을 담고 있는 XML 파일입니다. 한컴 고유의 복잡한 태그 체계로 구성되어 있어서, 일반적인 방법으로 내용을 수정하면 높은 확률로 파일이 깨집니다. 실제로 이 실습을 준비하면서도 여러 차례 파일이 손상되는 시행착오를 겪었습니다.

다행히 Claude의 doc-automation 스킬에는 이 문제를 해결한 코드가 이미 들어 있기 때문에, 사용하는 입장에서는 그냥 "바꿔줘"라고 말하기만 하면 됩니다.


## 실습 준비물

이번 실습에 사용할 파일은 다음과 같습니다.

- **원본_결재문서본문.hwpx** — 서울대공원 총무과에서 실제로 사용하는 결재문서 양식입니다. 기관 로고, 결재란 테이블, 수발신 영역이 모두 포함되어 있습니다.
- **서울불꽃축제_결과보고.hwpx** — 완성된 결과물입니다. 양식은 원본과 동일하고, 내용만 불꽃축제 보고서로 바뀌어 있습니다.


## 실습 진행

### Step 1: 원본 문서 확인하기

먼저 원본 결재문서를 한컴 오피스에서 열어 봅니다. 서울대공원 총무과의 보고서 작성 서식 안내 문서가 열리는 것을 확인할 수 있습니다. 기관 슬로건, 로고, 수신자 영역, 본문, 결재란, 하단 발신 정보까지 공문 양식이 빈틈없이 갖추어져 있습니다.

이 양식의 모든 요소를 그대로 유지하면서, 내용만 서울 불꽃축제 결과 보고서로 바꾸는 것이 이번 실습의 목표입니다.


### Step 2: AI에게 요청하기

Claude에게 원본 HWPX 파일을 첨부한 뒤, 다음과 같이 요청합니다.

> "이 결재문서 양식을 그대로 사용해서 서울 불꽃축제 운영 결과 보고서로 바꿔줘. 기관명은 한강사업본부, 담당자는 김한강, 결재자는 박여의로 해줘."

Claude는 원본 문서의 구조를 분석한 뒤, 양식은 건드리지 않고 텍스트만 치환하여 새로운 HWPX 파일을 생성합니다.

실제로 바뀌는 내용은 다음과 같습니다.

| 항목 | 원본 | 변경 후 |
|------|------|---------|
| 기관명 | 서울대공원 | 한강사업본부 |
| 제목 | 보고서 작성 서식 안내 | 2026 서울세계불꽃축제 운영 결과 보고 |
| 본문 | 보고서 서식 안내 관련 내용 | 축제 개최 결과 및 참여 인원 보고 |
| 결재자 직위 | 총무과장 | 한강사업본부장 |
| 담당자 | 강준민 | 김한강 |
| 결재자 | 이행용 | 박여의 |
| 수신자 | 전략기획실장, 운영과장 등 | 공원녹지정책과장, 안전총괄과장 등 |
| 연락처/주소 | 서울대공원 정보 | 한강사업본부 정보 |


### Step 3: 결과 확인하기

생성된 `서울불꽃축제_결과보고.hwpx`를 한컴 오피스에서 열어 봅니다.

원본 문서의 양식이 그대로 유지되면서, 내용만 불꽃축제 보고서로 바뀌어 있는 것을 확인할 수 있습니다. 기관 로고, 결재란 테이블, 수발신 영역의 레이아웃이 모두 원본과 동일합니다.


## 이런 식으로도 활용할 수 있습니다

이번에는 결재문서를 예시로 들었지만, 같은 방식으로 다양한 한글 문서에 적용할 수 있습니다.

매달 양식이 같은 월간 보고서를 작성해야 한다면, 이전 달 보고서를 첨부하고 "이번 달 데이터로 바꿔줘"라고 요청하면 됩니다. 인사발령 공문의 이름과 부서만 바꿔야 한다면, 기존 공문을 첨부하고 변경할 내용을 알려주면 됩니다. 계약서나 안내문처럼 날짜와 금액만 달라지는 문서도 마찬가지입니다.

핵심은 "양식은 건드리지 않고 내용만 바꾼다"는 점입니다. 한글 파일의 복잡한 구조를 이해할 필요 없이, AI에게 원본 파일과 바꿀 내용만 알려주면 됩니다.


## 참고: 내부적으로는 어떻게 동작할까?

기술적인 내용이 궁금한 분을 위해 간단히 설명하면, Claude는 내부적으로 다음 세 가지를 수행합니다.

첫째, HWPX 파일(ZIP)을 열어서 본문 XML 파일의 텍스트를 추출합니다. 둘째, 바꿔야 할 텍스트를 찾아서 새 텍스트로 교체합니다. 이때 XML 구조를 파싱하지 않고 순수 문자열 치환만 수행하기 때문에 원본의 레이아웃이 깨지지 않습니다. 셋째, 텍스트 길이가 바뀌면서 생기는 레이아웃 캐시 불일치 문제를 해결하기 위해, 캐시 데이터를 제거합니다. 한컴 오피스가 문서를 열 때 캐시를 자동으로 다시 생성하기 때문에 문제가 없습니다.
