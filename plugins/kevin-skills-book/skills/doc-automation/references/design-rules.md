# 디자인 규칙

build_deck이 기본 디자인을 처리한다. 이 문서는 outline을 고치거나 이미지 검수에서 문제를 발견했을 때 읽는다.

## 1. 차트 고르기

| 보여 줄 것 | 차트 | 주의 |
|------------|------|------|
| 시간에 따른 변화 | line | 범주(날짜) 4개 이상일 때 |
| 항목 간 크기 비교 | column(항목 7개 이하), bar(항목명이 길거나 8개 이상) | 큰 순서로 정렬 |
| 구성비 | pie / doughnut | 항목 5개 이하, 합계 100% |
| 구성의 변화 | stacked_column | 계열 4개 이하 |
| 정확한 값 비교가 중요 | 차트 대신 table | |

- 한 차트 = 한 메시지. 헤드라인이 그 메시지를 말한다
- 단위는 `unit`에 쓴다(차트 오른쪽 위에 표시)
- 숫자 축 시작이 0이 아니면 왜곡이 생긴다. 막대는 0부터

## 2. 표

- 12행 이하. 많으면 상위 N개 + "기타"로 묶는다(합계는 derived 선언)
- 첫 열은 항목명, 숫자 열은 같은 단위·같은 자릿수
- 강조할 행은 헤드라인이나 takeaway로 말한다(색으로만 강조하지 않는다)

## 3. KPI

- 2~4개. 대상의 관심 포인트에 직접 답하는 숫자만
- `delta`는 비교 기준이 분명할 때만(전주 대비, 목표 대비) — 기준은 label이나 note에 적는다

## 4. 글자

- 헤드라인 45자 이내, 본문 항목 2줄 이내, 상위 항목 6개 이하
- 글자가 넘치면 글자를 줄이지 말고 내용을 나눈다(build_deck은 최소 11pt까지만 줄인다)
- 한글 글꼴은 East Asian 글꼴로 지정된다. 회사 글꼴은 settings `font_family`

## 5. 피할 것

- 장식용 선·색 막대·그림자 남발(정보 없이 시선을 뺏는다)
- 같은 내용을 글머리와 차트에 중복
- 이미지 검수에서 보이는 겹침·잘림·빈 슬라이드
- 출처 없는 숫자, "약", "대략"으로 숫자 흐리기

## 6. 이미지 검수 체크리스트

render_slides.py로 만든 PNG를 장마다 보며 확인한다.

- [ ] 헤드라인이 한 줄 또는 두 줄 안에 들어간다
- [ ] 글자·도형·차트가 서로 겹치지 않는다
- [ ] 표·차트 숫자가 읽힌다(너무 작지 않다)
- [ ] 슬라이드 하단 출처·페이지 번호가 보인다
- [ ] 빈 칸, 템플릿 안내 문구가 없다
- [ ] 로고·회사 템플릿 요소가 콘텐츠를 가리지 않는다
