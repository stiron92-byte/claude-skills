# 정리(기능 1) 규칙과 기록 형식

## 1. 무엇을 바꾸고 무엇을 보고만 하는가

판단 기준은 하나다. **바꾼 결과가 원래 값보다 정보가 줄어들 수 있으면 바꾸지 않는다.**

| 대상 | 처리 | 이유 |
|------|------|------|
| 완전 중복 행(일련번호 열 제외 모든 값 같음) | 삭제, 첫 행 유지, `n행과 같음` 기록 | 정보 손실 없음 |
| 유사 중복(핵심 열만 같음) | 보고만(`유사중복_후보`) | 다른 값이 최신 정보일 수 있다 |
| 전화번호 `01012345678`, `010 1234 5678`, `+82-10-…` | `010-1234-5678`로 통일 | 자릿수가 맞으면 의미가 같다 |
| 전화번호 자릿수 오류, 영문 O·l 혼입 | 원래 값 유지 + 후보 | 어느 숫자가 빠졌는지 알 수 없다 |
| 날짜 `2024/03/05`, `2024.3.5`, `20240305`, `2024년 3월 5일`, 엑셀 일련번호 | `2024-03-05`로 통일 | 해석이 하나뿐 |
| 날짜 `03/04/2024`(월·일 둘 다 12 이하), `24-03-04`(두 자리 연도) | 원래 값 유지 + 후보 | 해석이 둘 이상 |
| 이메일 도메인 오타(`gamil.com`) | 보고 + 제안 도메인 | 실제 도메인일 수도 있다 |
| 극단값(사분위 범위 3배 밖) | 보고만 | 실제 값일 수 있다 |
| 범주 표기 흔들림(`서울 강남구`/`서울시 강남구`) | 보고 + 통일 제안 | 같은 값인지 사람이 정한다 |
| 범주 표기, 사용자 사전(`references/category-map.json`)에 있는 값 | 사전대로 통일, 기록 | 사용자가 정한 규칙 |
| 빈 칸 | 채우지 않음, `빈칸현황`에 열별 개수·행 | 채운 값은 지어낸 값이다 |

엑셀이 앞자리 0을 지운 휴대전화(`1012345678`, 숫자형)는 0을 붙여 통일한다. 숫자형으로 저장된 전화번호가 많으면 사용자에게 열 서식을 텍스트로 바꾸라고 알린다.

## 2. 결과 파일 구성

| 시트 | 내용 |
|------|------|
| 정리완료 | 정리된 데이터(원본과 같은 열 순서) |
| 변경리포트 | 입력·삭제·정리 후 행 수, 항목별 변경 수, 후보 수, 원본 변경 여부 |
| 변경내역 | 원본 행 · 열 · 이전 값 · 이후 값 · 사유 (삭제 행 포함) |
| 유사중복_후보 | 키 · 원본 행 · 행 전체 값 |
| 오타_이상값_후보 | 원본 행 · 열 · 값 · 사유 · 제안 |
| 빈칸현황 | 열 · 빈 칸 수 · 비율 · 원본 행 · 제안 |

"원본 행"은 원본 파일의 엑셀 행 번호다(머리글이 1행이면 첫 데이터는 2행). 사용자가 원본에서 바로 찾을 수 있어야 한다.

## 3. report.json 형식(verify_excel이 읽는다)

`clean_data.py`는 `<결과>.xlsx.report.json`을 함께 쓴다. 엔진 밖에서 정리를 더했다면 같은 형식으로 갱신해야 검증을 통과한다.

```json
{
  "input_sha256_before": "…", "input_sha256_after": "…",
  "sheet": "고객목록", "header": ["번호", "이름", "…"], "header_row": 1, "sequence_columns": ["번호"],
  "rows_in": 33, "rows_out": 31, "kept_src_rows": [2, 3, "…"],
  "removed": [{"src_row": 32, "duplicate_of": 4}],
  "changes": [{"src_row": 2, "column": "연락처", "before": "01068959668", "after": "010-6895-9668", "reason": "전화번호 형식 통일(휴대전화)"}],
  "candidates": [{"src_row": 6, "column": "연락처", "value": "010-777-888", "reason": "…", "suggestion": ""}],
  "blanks": [{"column": "지역", "count": 2}]
}
```

`kept_src_rows[i]`는 `정리완료` 시트 i번째 데이터 행이 원본 몇 행에서 왔는지다. 행 순서를 바꾸면 이 목록도 같은 순서로 바꾼다.

## 4. 엔진 밖 정리를 기록하는 법

주소를 시·구로 나누거나 이름에서 직함을 떼는 일처럼 엔진에 없는 정리는 pandas로 하되, 바꾼 셀마다 `changes`에 한 줄을 더한다.

```python
import json
rep = json.load(open(out + ".report.json", encoding="utf-8"))
for i, src_row in enumerate(rep["kept_src_rows"]):
    before = df.at[i, "주소"]
    after = before.replace("서울특별시", "서울")
    if after != before:
        df.at[i, "주소"] = after
        rep["changes"].append({"src_row": src_row, "column": "주소", "before": before, "after": after, "reason": "시·도 표기 통일(사용자 요청)"})
# df를 '정리완료' 시트에 다시 쓰고, 변경내역 시트에도 같은 줄을 더한 뒤 report.json 저장
```

열을 새로 만드는 경우(예: `시도` 열 추가)는 기존 열 값이 바뀌지 않으므로 기록 대상이 아니다. 새 열은 `정리완료` 맨 오른쪽에 둔다.

## 5. verify_excel clean 검사

| 검사 | 뜻 | 고치는 법 |
|------|----|-----------|
| input-changed | 원본 파일이 바뀌었다 | 원본을 백업에서 되돌리고 새 파일에 다시 작업 |
| missing-report | report.json이 없다 | clean_data.py로 정리하거나 3장 형식으로 기록 |
| row-count | 입력 = 정리 후 + 삭제가 아니다 | 기록 없이 지운 행을 되살리거나 removed에 기록 |
| bad-dedup | 중복으로 지운 행이 실제로 다르다 | 그 행을 되살린다. 유사 중복은 후보로 |
| unlogged-change | 기록 없는 셀 변경 | 변경을 되돌리거나 changes에 사유와 함께 기록 |
| candidate-modified | 후보로 보고한 값을 고쳤다 | 원래 값으로 되돌리고 사용자 결정을 기다린다 |
| blank-filled | 빈 칸을 채웠다 | 빈 칸으로 되돌린다(사용자가 값을 줬다면 changes에 기록) |
| missing-report-sheet | 변경리포트·변경내역 시트 없음 | 시트를 만든다 |
