# 취합(기능 3) — spec.json, 키 열, 레이아웃, 수식

## 1. 키 열 고르기

1단계 프로파일의 `공통 열(시트 간)`과 시트별 `키 후보`를 본다. 좋은 키는 다음을 모두 만족한다.

- 취합할 모든 탭에 같은 이름으로 있다(이름이 다르면 사용자에게 같은 열인지 확인)
- 탭 안에서 값이 겹치지 않는다(고유값 비율 0.95 이상, 빈 칸 없음)
- 사람이 바꾸지 않는 값이다(상품코드·사번 ○, 상품명·이름 △)

탭 안에서 키가 겹치면(같은 상품코드가 두 행) INDEX/MATCH는 첫 행만 가져온다. 이때는 취합 전에 사용자에게 알리고, 합계가 필요하면 4장의 SUMIFS를 쓴다.

## 2. spec.json

```json
{
  "key": "상품코드",
  "sheets": [
    {"sheet": "상품마스터", "columns": {"상품명": "상품명", "카테고리": "카테고리"}},
    {"sheet": "재고현황", "columns": {"총재고": "총재고"}},
    {"sheet": "스마트스토어", "columns": {"3월판매량": "스마트스토어_판매량", "3월매출": "스마트스토어_매출"}},
    {"sheet": "쿠팡", "columns": {"3월판매량": "쿠팡_판매량", "3월매출": "쿠팡_매출"}}
  ],
  "sums": {"전체_판매량": ["스마트스토어_판매량", "쿠팡_판매량"]},
  "count_nonblank": {"등록채널수": ["스마트스토어_판매량", "쿠팡_판매량"]},
  "missing_label": ""
}
```

| 항목 | 뜻 |
|------|----|
| `key` | 통합 기준 열 이름(각 탭에서 이름으로 찾으므로 위치가 달라도 된다) |
| `sheets[].columns` | `{원본 열 이름: 통합 시트 열 이름}`. 원본 열 이름은 1단계 프로파일에 나온 그대로 |
| `sums` | 여러 열의 합계 열(SUM 수식) |
| `count_nonblank` | 값이 있는 열 개수(예: 몇 개 채널에 등록되었나) |
| `missing_label` | 해당 탭에 없는 항목 표시. 기본은 빈 칸. 사용자 맞춤 `settings.yaml`의 `missing_label`도 쓸 수 있다 |

레이아웃 원칙: 마스터 정보(이름·분류) → 공통 지표(재고) → 탭별 지표(같은 지표끼리 같은 순서) → 합계·등록 수. 채널 비교가 목적이면 탭별 열 이름을 `<탭>_<지표>`로 통일한다.

## 3. 결과와 수식

- 맨 앞 `통합관리`(키 합집합 정렬, 머리글 고정), 둘째 `취합리포트`(키 열, 항목 수, 탭별 항목 수, 원본 탭 목록), 그 뒤 원본 탭 전부(손대지 않음)
- 조회: `=IFERROR(INDEX('쿠팡'!$D:$D,MATCH($A2,'쿠팡'!$A:$A,0)),"")`
- 합계: `=SUM(D2,F2,H2)` / 등록 수: `=SUMPRODUCT(--(LEN(CHOOSE({1,2},D2,F2))>0))`
- 끝에서 `recalc.py`가 Excel(또는 LibreOffice)로 계산해 저장하고 오류 셀을 센다
- 원본에 "이 시트에 취합해 주세요" 같은 안내만 있는 빈 탭이 있어도 그 탭은 고치지 않는다. 새 `통합관리` 시트에 만들고, 그 자리에 넣기를 원하면 알려 달라고 전달한다(시트 이름은 `--sheet-name`으로 바꿀 수 있다)

## 4. 엔진 밖 수식이 필요할 때

| 필요 | 수식 | 주의 |
|------|------|------|
| 같은 키가 여러 행(합계) | `=SUMIFS('쿠팡'!$D:$D,'쿠팡'!$A:$A,$A2)` | 없는 항목은 0이 된다(빈 칸과 구분 필요하면 COUNTIF로 감싼다) |
| 조건부 개수 | `=COUNTIFS(...)` | |
| 탭 이름에 공백·특수문자 | `'탭 이름'!` 작은따옴표 | 탭 이름에 `'`가 있으면 `''`로 |

쓰지 않는 함수: XLOOKUP, XMATCH, FILTER, UNIQUE, SORT, SEQUENCE, LET, LAMBDA(Excel 2019 이하·LibreOffice에서 #NAME? 오류). verify가 막는다.
직접 수식을 넣은 뒤에는 반드시 `recalc.py`를 돌리고 `verify_excel.py consolidate <원본> <결과> --sheet 통합관리 --key 상품코드`로 검사한다.

## 5. verify_excel consolidate 검사

| 검사 | 뜻 | 고치는 법 |
|------|----|-----------|
| original-sheet-missing / original-sheet-changed | 원본 탭이 빠졌거나 바뀌었다 | 원본 파일에서 다시 시작(원본 탭은 읽기만) |
| missing-keys / extra-keys / duplicate-keys | 통합 키가 원본 탭 키의 합집합과 다르다 | 모든 탭의 키를 합집합으로, 중복 없이 |
| values-pasted | 수식이 아닌 값 | INDEX/MATCH 수식으로 바꾼다 |
| wrong-column | 수식이 spec과 다른 원본 열을 참조 | spec·열 문자 확인 |
| lookup-mismatch | 계산값이 원본 탭을 직접 찾은 값과 다르다 | 키 열·값 열 참조 확인, 키 자료형(숫자/문자) 통일 |
| not-recalculated | 계산값이 없다 | `recalc.py` 실행. 엔진이 없으면 `--allow-uncached`로 경고 처리하고 사용자에게 Excel로 열어 저장하라고 안내 |
| formula-error / forbidden-function | 오류 셀·호환 안 되는 함수 | 수식 수정 |
