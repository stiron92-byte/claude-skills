# HWPX 편집 가이드

치환이 잘 되지 않거나 결과가 이상할 때 읽는다.

## 1. 구조

| 엔트리 | 내용 | 편집 |
|--------|------|------|
| `mimetype` | `application/hwp+zip`. 반드시 첫 엔트리·무압축 | 건드리지 않음 |
| `Contents/section0.xml` … | 본문(문단·표·글상자) | 텍스트 노드만 |
| `Contents/header.xml` | 글꼴·문단 모양·스타일 정의 | 건드리지 않음 |
| `Contents/content.hpf` | 패키지 목록·메타데이터 | 건드리지 않음 |
| `BinData/` | 로고·직인 등 이미지 | 건드리지 않음 |
| `settings.xml`, `version.xml` | 설정 | 건드리지 않음 |

본문 글자는 `<hp:t>…</hp:t>` 안에 있다. 문단은 `<hp:p>`, 같은 문단 안에서 글자 모양이 바뀌면 `<hp:run>`이 나뉜다.

## 2. 글자가 조각으로 나뉘는 경우

"2. 전부서에서는 붙임 “보고서 서식”을 참조하여"처럼 따옴표·굵게·색이 섞인 문장은 조각 3개로 나뉜다.

```
조각 1: 2. 전부서에서는 붙임
조각 2: “보고서 서식”
조각 3: 을 참조하여 …
```

- `extract`(조각)와 `extract --paragraphs`(문단)를 비교하면 나뉜 위치가 보인다.
- 조각마다 따로 치환하거나, 양식을 바꿔도 되면 한컴오피스에서 해당 문장의 서식을 하나로 맞춘 뒤 다시 저장한다.
- 조각에 걸친 문장을 억지로 하나로 합치려고 XML을 직접 고치지 않는다.

## 3. linesegarray

`<hp:linesegarray>`는 줄마다 글자가 어디서 끊기는지 미리 계산해 둔 캐시다.
글자 길이가 바뀌었는데 캐시가 남아 있으면 한컴오피스가 옛 위치대로 그려 글자가 겹친다.
스크립트는 내용을 바꾼 XML에서만 이 캐시를 지운다. 한컴오피스가 열 때 다시 계산한다.

## 4. 자주 나는 문제

| 증상 | 원인 | 조치 |
|------|------|------|
| `PLAN MISSING` | 원문 띄어쓰기·특수문자 불일치, 조각 분할 | extract 결과를 그대로 복사, 조각 단위로 분할 |
| 한컴오피스에서 "파일이 손상" | 파서로 다시 쓴 XML, mimetype 위치·압축 | 이 스킬 스크립트로 다시 생성, verify 실행 |
| 결재란 글자가 칸을 넘침 | 새 글이 원래보다 김 | 원래 글자 수 ±30% 안으로 줄임 |
| 의도하지 않은 곳도 바뀜 | 같은 원문이 여러 곳 | 앞뒤 조각까지 포함한 긴 원문 사용 |
| `.hwp` 파일 | 구버전 바이너리 형식 | 한컴오피스에서 HWPX로 다시 저장 |
| 암호 걸린 문서 | 내용 암호화 | 암호를 해제한 사본으로 진행 |

## 5. 공문서 문체 메모

- 종결: "~하였습니다", "~하고자 합니다", "~바랍니다"
- 붙임 마지막 줄 끝에 "끝." (두 칸 띄움 관례가 있는 기관이 많다. 원본 표기를 따른다)
- 날짜: 원본 표기(2026. 10. 10. / 2026-10-10)를 따른다
