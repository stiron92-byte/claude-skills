## 2. 비교 평가 (skill-creator 방식)

조건은 다음과 같다.

- 같은 입력과 같은 Python 환경(pins-venv)을 썼다.
- 실행마다 새 하위 에이전트(Opus 5.5)로 1회 실행했다.
- 기준선은 v1.6.1 스냅샷이다.
- 채점은 `tools/grade_excel_runs.py`가 맡았다. 결과 파일을 머리글 내용으로 찾아 정답표와 대조하고, 수식은 사본을 Excel로 재계산해 읽는다.
- [판단] 항목은 결과 파일과 최종 응답을 읽고 판정했다(`judgments.json`).

| eval | 내용 | v2 | v1.6.1 |
|------|------|:--:|:------:|
| 1 | 고객 명단 정리(실습1) | 11/11 | 11/11 |
| 2 | 쇼핑몰 매출 분석(실습2) | 10/10 | 8/10 |
| 3 | 멀티채널 탭 취합(실습3) | 10/10 | 10/10 |

| 지표(평균) | v2 | v1.6.1 |
|------------|:--:|:------:|
| 기대 항목 통과율 | 1.00 | 0.93 |
| 실행 시간 | 148초 | 245초 |
| 토큰 | 12.9만 | 14.3만 |

v1.6.1이 놓친 항목(eval 2)
- 인사이트 숫자 6개가 통합 문서 어느 셀에도 없다. 예를 들어 "3개월 3,009만 원(34.2%)"과 "후반 6개월 4,633만 원 대 전반 4,177만 원(10.9%)"이 그렇다. 계산은 맞을 수 있지만 받는 사람이 파일에서 확인할 수 없다. v2는 같은 종류의 계산값을 `추가지표` 시트에 먼저 쓰고 근거 셀을 적었다.
- 12월 객단가 하락을 "선물용 저가 상품 비중이 커졌기 때문"이라고 단정했다. 구매 목적은 데이터에 없다. 경계 사례로, 같은 문서의 다른 원인 추정은 "보이며"로 완화되어 있었다.

해석할 때 주의할 점
- 하위 에이전트가 강한 모델이라 v1.6.1에서도 결과 품질이 높았다. 원본 보존, 후보 비수정, 유사 중복 보고, INDEX/MATCH 수식, 오류 0을 v1.6.1도 해냈다. 즉 v1.6.1 점수는 모델이 스킬의 코드 예시를 넘어서 스스로 잘한 결과다. v2의 이점은 점수 차이보다 **같은 결과를 검증 가능한 절차로 더 빨리** 낸다는 데 있다(시간 −40%, 토큰 −10%, 결과마다 `VERIFY OK`).
- 약한 모델이나 낯선 데이터에서는 차이가 더 클 것으로 예상하지만 측정하지 않았다. 실행이 1회씩이라 분산도 모른다.
- skill-creator `aggregate_benchmark`의 요약 줄은 Delta를 "-0.07"로 표시한다(부호 방향이 반대). `tools/check_benchmark.py`의 계산은 +0.067이다.
- 평가 후 `references/consolidation.md`에 안내 문구만 있는 빈 탭 처리 규칙 한 줄을 더했다. 평가에 쓴 스냅샷에는 없다.

사람 검토용 정적 뷰어는 `.workspace/excel-automation-workspace/iteration-1/review.html`이다. 로컬 파일이며 커밋 대상이 아니다.

## 4. 검증 장치와 양성 대조

| 검사 | 내용 |
|------|------|
| `tests/check_excel_practice_inputs.py` | 생성기 재현성, 정답표를 원본에서 독립 재계산해 대조, 값 하나를 바꾼 사본이 실패하는지(양성 대조), 카탈로그 재분류 |
| `tests/check_excel_clean.py` | 정리 엔진 결과를 정답표와 대조. 같은 비교를 정리 전 원본에 적용하면 48건 불일치(양성 대조) |
| `tests/check_excel_consolidate.py` | 원본 탭 보존, 키 108개, 채널별 합계·등록 수, 수식 오류 0. 결과 파일의 쿠팡 탭 한 칸을 바꾸고 재계산하면 통합 합계가 같은 만큼 바뀌는지(수식 연결 양성 대조) |
| `tests/check_verify_excel.py` | 정상 결과 3종 통과 + 결함 20종(원본 변경, 행 수, 후보 수정, 기록 없는 변경, 빈 칸 채움, 잘못된 중복 삭제, 기록 없음, 원본 탭 누락·변경, 키 누락, 값 붙여넣기, 호환 안 되는 함수, 수식 오류, 조회값 불일치, 재계산 안 함, 출처 없는 인사이트 숫자, 차트 없음, 인사이트 없음, 분석 중 원본 변경, 원본 덮어쓰기)을 각각 검출. 만 단위 반올림 표기는 통과 |
| `tools/grade_excel_runs.py` 대조 | 정리하지 않은 원본을 결과로 넣으면 행 수·전화·날짜·오타 표시·변경 내역 항목이 실패 |

CI 러너에는 Excel·LibreOffice가 없다. 그래서 CI에서는 취합·verify 대조를 `--allow-no-engine`으로 돌려 수식 구조만 확인한다. 계산값 대조는 로컬 게이트(E3·E4)가 Excel로 확인한다.

## 5. 남은 것

- 트리거 실측은 하지 않았다. excel-automation용 트리거 eval 세트도 아직 없다. CLI 로그인 후 doc-automation과 같은 방식으로 측정한다(handoff H10).
- 실행 1회씩이다. 예산이 되면 eval당 3회로 분산을 본다.
