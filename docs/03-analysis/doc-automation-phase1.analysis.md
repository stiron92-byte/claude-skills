## 2. 비교 평가 (skill-creator 방식)

조건: 같은 입력, 같은 Python 환경, 실행마다 새 하위 에이전트(Opus 5.5) 1회. 기준선 = v1.6.1 스냅샷. 채점은 두 구성 모두 같은 독립 출처(원래 입력을 다시 추출)와 같은 검증기로 했다.

| eval | 내용 | v2 | v1.6.1 |
|------|------|:--:|:------:|
| 1 | 환율 PDF → 과장 보고(책 실습 2-3) | 7/7 | 6/7 |
| 2 | 회사 문서 6개 + 공고 + 로고 → 팁스 발표 | 7/7 | 7/7 |
| 3 | 주간 매출 CSV → 팀장 보고 + 임원 메일 | 6/6 | 3/6 |
| 4 | 4:3 회사 템플릿 적용 | 5/5 | 4/5 |

| 지표(평균) | v2 | v1.6.1 |
|------------|:--:|:------:|
| 기대 항목 통과율 | 1.00 | 0.79 |
| 실행 시간 | 281초 | 340초 |
| 토큰 | 17.0만 | 18.2만 |

v1.6.1이 놓친 항목
- 헤드라인이 주제명이라("보고 요약", "일별 매출 추이") 대상의 질문에 대한 답이 제목에 없음(eval 1, 3)
- CSV에서 계산한 비중·평균(79%, 일평균 842만 원 등)이 출처·계산식 없이 들어가 대조 불가(eval 3, 4)
- 차트가 matplotlib 이미지라 받는 사람이 고칠 수 없음(eval 3)

주의: 하위 에이전트가 강한 모델이라 v1.6.1에서도 스킬 스크립트를 우회해 직접 덱을 만든 경우가 많았다(4건 중 4건). 즉 v1.6.1 점수는 "스킬 품질"보다 "모델이 스킬을 우회한 결과"에 가깝다. v2는 스킬 절차를 그대로 따랐고 사후 보정 없이 통과했다. 실행 1회씩이라 분산은 측정하지 못했다.

hwpx-editor(책 실습 2-6, 2-7): 2건 모두 9/9 항목 통과. 사용자가 주지 않은 날짜·수치는 지어내지 않고 ○○로 남겼다.

사람 검토용 정적 뷰어: `.workspace/doc-automation-workspace/iteration-1/review.html`(로컬, 커밋 대상 아님)

## 4. 트리거 평가

- 실제 측정(`claude -p` 기반 run_trigger_eval.py)은 이 PC의 Claude CLI 로그인이 만료되어 실행하지 못했다(GATES P10 handoff). 공식 skill-creator의 run_eval.py는 Windows에서 동작하지 않아(`select.select`를 파이프에 사용) Windows 호환 러너를 새로 만들었다.
- 대리 지표(참고용): 독립 하위 에이전트에게 이 PC의 스킬 목록(업무 플러그인 7종 + 공식 pptx·docx·xlsx·pdf)과 질의 20개를 주고 선택을 물었다. should-trigger 10/10 적중, near-miss 10개 중 오발동 0. 실제 라우팅 메커니즘이 아니므로 로그인 후 실측으로 대체해야 한다.

## 5. 공식 도구 사용 중 확인한 Windows 제약

- skill-creator `scripts/aggregate_benchmark.py`, `eval-viewer/generate_review.py`: 인코딩 없이 파일을 열어 한국어 Windows(cp949)에서 실패 → `PYTHONUTF8=1`로 실행
- skill-creator `scripts/run_eval.py`: 파이프에 `select.select` 사용 → Windows 불가 → `tools/run_trigger_eval.py`로 대체
- `claude plugin eval`: 이 계정에서 early access 비활성
