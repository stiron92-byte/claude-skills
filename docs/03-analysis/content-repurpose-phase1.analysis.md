## 2. 비교 평가 (skill-creator 방식)

조건은 다음과 같다.

- 같은 입력, 같은 Python 환경, 실행마다 새 하위 에이전트(Opus 5.5) 1회, 오늘 날짜 2026-10-02를 알려 줌.
- 채점은 `tools/grade_repurpose_runs.py`가 결과 텍스트를 정답표와 플랫폼 규칙으로 검사했다. [판단] 항목은 결과와 최종 응답을 읽고 판정했다.

| 반복 | eval | v2 | v1.6.1 |
|------|------|:--:|:------:|
| iteration-1 | 감사(책 8-1)·갭(책 8-2)·블로그+X+인스타·링크드인+뉴스레터 | 1.00 | 1.00 |
| iteration-2 | 위 4개 + 짧은 형식 3종(쇼츠·Threads·핀터레스트) + 영어 X 스레드 | 1.00 | 1.00 |

| 지표(iteration-2 평균) | v2 | v1.6.1 |
|------------------------|:--:|:------:|
| 통과율 | 1.00 | 1.00 |
| 실행 시간 | 138초 | 147초 |
| 토큰 | 13.2만 | 12.4만 |

**결과: 두 구성 사이에 측정 가능한 차이가 없다.** 게이트 R8("새 스킬이 더 높고 0.8 이상")은 충족하지 못했고, 원장에 포기(ABANDON)와 사유로 남겼다.

- iteration-1에서 두 구성 모두 만점이 나와(천장 효과) 평가가 차이를 가려내지 못했다.
- 그래서 iteration-2 실행 전에 eval 2개를 추가했다. 근거는 계획서 §1.2(6)에 미리 적힌 위험이다: 짧은 형식의 실제 한도, 영어 X 가중치. v1.6.1이 실패할 지점을 결과를 보고 고른 것이 아니다.
- 두 번째도 만점 동률이었다. 강한 모델은 v1.6.1의 지시만으로도 한도·숫자·형식을 스스로 지켰다.
- 실행 시간은 v2가 약 6% 짧고 토큰은 약 6% 많다. 실행 1회씩이라 이 차이는 잡음 범위다.

### 점수에 잡히지 않은 차이

| 관찰 | v2 | v1.6.1 |
|------|----|--------|
| 스킬이 함께 배포하는 예시 | 검증 통과, 원본 숫자만 사용 | 원본에 없는 숫자 4개와 틀린 계산식(검증기로 검출) |
| 글자 수 근거 | 스크립트 측정값(트윗별 가중치) | 모델의 자기 보고(이번 평가에서는 맞았다) |
| 재현 가능한 감사 수치 | 스크립트 집계 + 판단 구분 | 모델 집계(이번 평가에서는 맞았다) |
| 약한 모델·사람 사용자 | 측정 안 함 | 측정 안 함 |

v2의 가치는 "더 좋은 결과"가 아니라 "같은 결과를 검증 가능하게 낸다"에 있다. 이 주장도 이번 평가로 증명되지는 않는다. 약한 모델이나 실제 사용자 세션에서 측정해야 차이가 보일 수 있다(§5).

## 3. 채점기 수정 — 결과를 본 뒤에 바꾼 것

결과를 읽으며 채점기의 오판을 찾아 고쳤다. 모두 v1.6.1 쪽 결과를 실패로 잘못 판정하던 것이라, 고친 뒤 v1.6.1 점수가 올라갔다.

| 오판 | 수정 |
|------|------|
| 블로그 본문의 `##` 소제목을 새 섹션으로 봐서 본문 뒷부분(단서 포함)이 빠짐 | 플랫폼이 아닌 소제목은 본문에 붙임. "요약"·"참고" 제목에서만 끊음 |
| 소제목 "뉴스레터 구독자를 늘린 3가지 변화"를 뉴스레터 플랫폼으로 인식 | 플랫폼 이름 외 단어가 일반 단어(본문·캡션·게시물 등)일 때만 플랫폼 제목 |
| 인스타 캐러셀 규격 "1080x1350"을 원본에 없는 숫자로 판정 | 이미지 규격·비율 제외 |
| 섹션 안에 붙은 요약 표의 숫자를 트윗 글자 수·숫자 출처로 셈 | 소셜 섹션의 표 줄은 게시 본문에서 제외 |
| "**핀 제목**" 다음 줄에 쓴 제목을 못 읽음 | 굵은 라벨 다음 줄도 인정 |
| 쇼츠 대사를 표와 "내레이션 전문"에서 두 번 셈 | "내레이션 전문"이 있으면 그 부분만 셈 |

앞의 두 수정과 이미지 규격 예외는 스킬 자체의 `count_chars.py`·`check_repurpose.py`에도 같은 결함이었으므로 함께 고쳤다(테스트 추가).
