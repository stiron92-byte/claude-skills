## 📌 챕터 1: 2시간의 기적, Claw Code (1:30 ~ 4:30)

**[화면: 샌프란시스코 야경 → 코드 에디터에서 빠르게 스크롤되는 코드 → GitHub 레포 스크린샷]**

**내레이션:**
유출 직후, 샌프란시스코에 있던 한국인 엔지니어 그룹이 움직였습니다. 박진형, 일명 Sigrid Jin을 중심으로 한 이 그룹은 유출된 코드를 기반으로 AI 모델에게 전체 코드베이스를 Python과 Rust로 재작성시켰습니다.

걸린 시간? 단 2시간.

**[화면: "50만 줄 → 2시간" 인포그래픽 / 서브에이전트 구조도 다이어그램]**

이른바 '메타 하네스' 전문가들이 서브 에이전트를 대량으로 돌려서 50만 줄의 코드를 완전히 포팅해낸 겁니다. 이 프로젝트의 이름은 Claw Code.

**[화면: GitHub 스타 비교 차트 — Claw Code vs Kubernetes vs Node.js vs Go vs Rust]**

그리고 이 Claw Code는 GitHub에서 Kubernetes, Node.js, Go, Rust 같은 레전드 오픈소스 프로젝트보다 더 많은 스타를 받았습니다. 포크만 10만 회를 넘겼죠.

그런데 여기서 아이러니한 포인트가 있습니다.

**[화면: "이건 밈이다" — 텍스트 크게 등장]**

사이오닉의 고석현 대표가 당사자인 박진형에게 직접 물었을 때, 돌아온 답은 "이건 밈이다"였습니다. 실제로 코드는 거의 동작하지 않는, 개념도 수준의 것이었죠. 사람들은 코드의 품질이 아니라 이 사건의 "의미"에 스타를 눌렀던 겁니다.

GitHub 스타의 문법 자체가 바뀌어버린 순간이었습니다. 코드의 품질이 아니라, 바이럴과 밈의 문법으로 스타가 부여되는 시대가 온 거죠.

## 📌 챕터 2: AI가 쓴 50만 줄의 실체 (4:30 ~ 8:00)

**[화면: Claude Code 내부 코드 구조도 / "AI-generated code" 텍스트 오버레이]**

**내레이션:**
유출된 코드를 분석하면서 한 가지가 확인됐습니다. Anthropic이 공언했던 "우리 코드의 대부분은 AI로 작성된다"는 말이 사실이었다는 겁니다.

**[화면: 코드 비교 — "사람이 읽기 좋은 코드" vs "모델이 처리하기 좋은 코드" 좌우 분할]**

50만 줄의 코드는 사람이 읽고 유지보수하기 좋은 형태가 아니었습니다. 소위 human interpretability가 전혀 고려되지 않은 구조였죠. 대신 모델이 짜기 좋고, 모델에 입력하기 좋은 형태로 철저하게 최적화되어 있었습니다.

전문가들의 평가는 직설적이었습니다. "가비지다." 하지만 동시에 이런 반론도 나왔죠. "명세가 정확하고 그걸 만족하는 구현이라면, 코드의 아름다움이 그렇게 중요한가?"

**[화면: 토큰 캐싱 최적화 프로세스 다이어그램 — 프롬프트 정렬 → 캐시 히트 → GPU 절감]**

그런데 진짜 흥미로운 부분은 따로 있었습니다. Claude Code의 핵심 경쟁력은 모델 성능 자체가 아니라 토큰 캐싱에 대한 집착적인 최적화에 있었습니다.

프롬프트를 정렬해서 캐시 히트율을 극대화하고, Anthropic 내부의 GPU 사용량을 줄이는 엔지니어링. 이것이 Claude Code의 진짜 무기였던 겁니다.

**[화면: Claude Code + Gemini, Claude Code + Codex 조합 다이어그램]**

실제로 신정규 대표는 Claude Code의 하네스에 Gemini를 붙이면 오히려 더 좋은 것 같다는 의견까지 냈습니다. 다른 모델을 붙여도 하네스가 잘 동작한다는 건, Claude Code의 가치가 모델이 아니라 하네스에 있었다는 뜻입니다.

Anthropic이 세계에서 가장 성공한 소프트웨어 제품 중 하나를 AI로 만들었고, 코드 품질은 떨어지지만 사용자 경험에 집중해서 시장을 이겼다. 이 사실이 역설적으로 증명된 셈이죠.

## 📌 챕터 3: 클린룸 논쟁 — AI 재작성은 저작권 침해인가 (8:00 ~ 12:00)

**[화면: "클린룸(Clean Room)" 정의 텍스트 카드]**

**내레이션:**
여기서 가장 뜨거운 논쟁이 시작됩니다. 클린룸 개발이란, 원본 코드의 내부를 전혀 모른 상태에서 외부 동작만 분석해 동일하게 만드는 방식을 말합니다.

Claw Code 팀은 "우리는 AI 모델을 사용해 다른 언어로 재구축했다"고 밝혔습니다. 전통적인 저작권법 기준으로 보면 동일한 코드 구문이 전혀 없죠.

**[화면: Claw Code 레포 README 발췌 — "코드를 보고 재작성했다" 문구 하이라이트]**

그런데 레포에는 "코드를 봤다"고 명시되어 있었습니다. 엄밀한 정의의 클린룸이 될 수 없는 거죠. 당사자들도 이걸 숨기진 않았습니다. "우리 코드도 아니며, Anthropic의 허락도 받지 않았고, 코드를 보고 재작성한 것이라고" 분명히 밝혔으니까요.

**[화면: 양쪽 화살표 다이어그램 — Anthropic의 기존 입장 vs 이번 대응]**

그리고 여기서 아이러니한 상황이 벌어집니다.

Anthropic은 그동안 "AI로 재작성되고 해석된 것은 추론과 학습에 의한 것이므로 저작권 문제가 없다"고 주장해왔습니다. 이건 AI 업계 전체의 일관된 입장이기도 했죠.

그런데 자사 코드가 유출되자 DMCA를 들이밀었습니다. 다만 흥미롭게도, AI로 리라이팅된 Claw Code에 대해서는 삭제 요청을 보내지 않았습니다.

**[화면: "자가당착" 텍스트 + Anthropic 로고]**

이 자가당착이야말로 이 사건의 핵심입니다. 남의 코드를 AI로 학습하는 건 괜찮은데, 내 코드를 AI로 재작성하는 건 안 된다? Anthropic 스스로도 이 질문에 명확한 답을 내리지 못하고 있는 것처럼 보입니다.

**[화면: 커뮤니티 반응 모자이크 — 트위터, GeekNews, 디스코드 캡처]**

커뮤니티의 반응은 첨예하게 갈렸습니다. "다른 사람의 핵심 IP를 적극적으로 활용한 건 도덕적으로 잘못이다"라는 의견에는 거의 모두가 동의했지만, "그러면 Anthropic이 학습한 수많은 오픈소스 코드는?" 이라는 반론 앞에서는 누구도 명쾌한 답을 내지 못했습니다.

고석현 대표의 정리가 인상적이었습니다. "클린룸이냐 아니냐, 이게 정답이냐 아니냐보다 중요한 건, 이 사건을 둘러싼 상황이 굉장히 입체적이라는 것이다."

## 📌 챕터 4: 소스코드 가치가 0에 수렴하는 시대 (12:00 ~ 15:30)

**[화면: 그래프 — "소스코드의 가치" 하락 곡선 / "하네스 엔지니어링의 가치" 상승 곡선 교차]**

**내레이션:**
이 사건이 진짜로 던지는 질문은 따로 있습니다. 소스코드의 가치는 얼마인가?

생각해보면 이런 일은 처음이 아닙니다. 유튜브는 초창기 불법 영화 공유 사이트였습니다. 남의 IP 위에서 회원을 모았고, 세상이 바뀌면서 합법적인 플랫폼이 됐죠. 법이 세상을 바꾼 게 아니라, 기술이 세상을 바꾸면서 법이 뒤따라간 겁니다.

**[화면: "PRD 몇 개 → AI → 완성된 코드" 플로우 차트]**

지금은 PRD 몇 개만 있으면 코드가 나오는 시대입니다. 소스코드를 직접 본 것과, 작동하는 제품의 UX만 보고 복제하는 것의 차이가 빠르게 사라지고 있습니다.

이 논의는 사실 더 큰 그림과 연결됩니다.

**[화면: 파이프라인 다이어그램 — 모델(Semantic CPU) → 하네스(OS) → 비즈니스 로직(앱)]**

모델은 이제 semantic CPU입니다. 하네스는 그 위의 운영 체제고요. 하네스 위에 올라가는 비즈니스 로직이 실제 회사의 제품이 되는 구조입니다. Claude Code가 보여준 건, 이 하네스 레이어의 설계 — 토큰 효율화, 컨텍스트 관리, 에이전트 제어 — 이것이 진짜 경쟁력이라는 사실입니다.

**[화면: "앞으로 나오는 모든 하네스와 오픈소스가 갑자기 굉장히 좋아질 것이다" 텍스트 카드]**

사이오닉 고석현 대표는 이렇게 말했습니다. "여러 그룹과 이야기를 나눠봤는데, 모두가 공통적으로 동의하는 게 있다. 앞으로 나오는 모든 하네스와 오픈소스들이 갑자기 굉장히 좋아질 것이다."

드러내고 한 사람은 비판을 받고, 드러내지 않고 흡수하는 사람은 제품이 좋아지는 겁니다. 우수한 유전자가 시장에 배포된 이상, 모두가 가져다 쓸 수밖에 없는 구조가 된 거죠.

## 📌 챕터 5: 보안 공급망 위기와 AI 코드의 미래 (15:30 ~ 17:00)

**[화면: 보안 경고 아이콘 + "Supply Chain Attack" 텍스트 → LiteLLM, Axios 로고]**

**내레이션:**
이 사건과 맞물려 또 하나의 큰 흐름이 보입니다. AI가 생성하는 코드와 보안 문제의 결합입니다.

같은 시기에 LiteLLM, Axios 관련 공급망 공격이 화제가 됐고, Andrej Karpathy까지 트윗으로 우려를 표했습니다. AI로 코드를 딸깍딸깍 만들다 보면 취약한 라이브러리를 무심코 가져다 쓰게 되고, 제로데이에 노출되는 겁니다.

**[화면: "생성 속도 >>>>>> 관리 속도" 비대칭 그래프]**

코드를 만드는 속도는 폭발적으로 빨라졌는데, 관리하는 속도는 따라가지 못하고 있습니다. 이 비대칭이 만들어내는 기술 부채는, 이메일 시대의 스팸처럼 코드 생태계 전체에 퍼질 수 있습니다.

하지만 역설적으로 AI가 만든 문제는 AI로 해결될 가능성도 있습니다. 고석현 대표의 제안처럼, 모든 코드베이스를 AI로 내재화하면 외부 라이브러리 의존성에 의한 공격은 줄일 수 있죠. 물론 AI가 만든 코드 자체의 취약점은 또 다른 문제지만요.
