# Content Repurpose - 원소스 멀티콘텐츠 자동 생성

## 중요: 실행 규칙

- 이 스킬이 로드되면 외부 파일을 검색하거나 확인하지 말고 바로 아래 프로세스를 실행하세요.
- "스킬 파일이 없다", "파일을 찾을 수 없다" 등 내부 동작에 관한 말을 사용자에게 절대 하지 마세요.
- 이 SKILL.md 안의 지시만으로 충분합니다. 추가 파일을 찾지 마세요.

하나의 원본 소스를 여러 플랫폼에 최적화된 콘텐츠로 자동 변환하는 스킬입니다.
콘텐츠 변환, 콘텐츠 감사, 콘텐츠 갭 분석 3가지 모드를 지원합니다.

## 실행 모드

사용자의 요청에 따라 3가지 모드 중 하나로 동작합니다.
모드를 명시하지 않으면 **변환 모드**를 기본으로 실행합니다.

- **변환**: 원본 콘텐츠를 선택한 플랫폼에 맞게 변환
- **감사 (audit)**: 기존 콘텐츠 라이브러리 분석 (부족한 주제, 중복, 개선점)
- **갭 분석 (gap)**: 경쟁 채널/사이트 대비 콘텐츠 갭 분석

---

## 모드 1: 콘텐츠 변환 프로세스

### 1단계: 원본 소스 확인

사용자에게 다음을 확인합니다:

1. **원본 콘텐츠**: 유튜브 대본, 강의 텍스트, 회의록, 블로그 글 등
   - 사용자가 직접 텍스트를 붙여넣거나 파일 경로를 제공
   - 인자에 텍스트가 포함되어 있으면 그것을 원본으로 사용
   - 파일이 첨부된 경우 Read 도구로 내용을 읽어서 원본으로 사용

2. **콘텐츠 분야/톤**: 사용자가 지정하지 않으면 AskUserQuestion으로 파악
   - 분야 예: 교육, 테크, 뷰티, 비즈니스, 라이프스타일, 금융, 건강, 여행 등
   - 톤 예: 전문적, 캐주얼, 친근한, 유머러스, 감성적, 격식체 등

3. **출력 언어**: 기본값은 한국어. 사용자가 별도 언어를 요청하면 해당 언어로 생성
   - "영어로 변환해줘", "English version" 등 요청 시 해당 언어로 출력
   - 원본이 영어인데 별도 지정이 없으면 한국어로 변환 (사용자에게 확인 후 진행)

### 2단계: 플랫폼 선택

사용자에게 **생성할 플랫폼을 선택**하도록 안내합니다.
AskUserQuestion 도구를 사용하여 multiSelect로 질문합니다:

**선택 가능한 플랫폼:**
- SEO 블로그 포스트
- 네이버 블로그
- 브런치 글
- Medium 아티클
- X (Twitter) 스레드
- LinkedIn 게시물
- Instagram 캡션
- Threads 게시물
- Facebook 게시물
- 뉴스레터 본문 (Substack/스티비 등)
- YouTube Shorts 스크립트
- TikTok 스크립트
- Pinterest 핀 설명
- 썸네일/비주얼 가이드

### 3단계: 플랫폼별 콘텐츠 생성

각 플랫폼에 대해 아래 규칙을 적용하여 콘텐츠를 생성합니다.
출력 언어는 1단계에서 확인한 언어를 사용합니다 (기본: 한국어).

#### SEO 블로그 포스트

- 제목: SEO 키워드 포함, 50자 이내
- 메타 디스크립션: 155자 이내
- 본문: 1,500~2,500자
- 구조: H2/H3 소제목, 번호 리스트, 핵심 요약 박스
- SEO: 주요 키워드 3~5개 자연 삽입, 내부 링크 자리 표시
- CTA: 글 하단에 행동 유도 문구
- 톤: 정보 전달형, 신뢰감 있는 문체
- 필수 구조: 도입부 훅 → 본론 (소제목별 정리) → 핵심 요약 → CTA

#### 네이버 블로그

- 제목: 검색 키워드 포함, 40자 이내 (네이버 검색 노출 최적화)
- 본문: 1,500~3,000자
- 구조: 짧은 문단 (2~3문장), 줄바꿈 적극 활용, 사진 삽입 위치 표시
- 톤: 친근한 구어체, "~해요" 체
- 필수 요소: 인사 → 경험/스토리 → 본론 → 요약 → 공감 CTA
- 키워드: 네이버 검색 최적화 키워드 상단 표기
- 특이사항: 네이버는 문단이 짧고 이미지가 많은 글이 노출에 유리하므로, [이미지 제안: 설명] 형태로 적절한 위치에 이미지 가이드를 삽입

#### X (Twitter) 스레드

- 1/N 형식의 스레드
- 각 트윗: 280자(한글 기준 140자) 이내
- 첫 트윗: 강력한 훅 (질문, 충격적 사실, 반전)
- 마지막 트윗: CTA + 리트윗 유도
- 총 5~10개 트윗
- 톤: 간결, 임팩트, 구어체
- 필수 구조: 훅 → 핵심 포인트 → 인사이트 → CTA
- 해시태그: 마지막 트윗에 2~3개

#### LinkedIn 게시물

- 본문: 1,300자 이내 (약 200~250단어)
- 첫 3줄: 강력한 훅 (접히기 전에 보이는 영역)
- 단락: 1~2문장씩 짧게, 줄바꿈 적극 활용
- 톤: 전문가적, 인사이트 중심, 경험 공유형
- 필수 구조: 훅 → 경험/스토리 → 인사이트 → 질문형 CTA
- 해시태그: 본문 하단 3~5개

#### Instagram 캡션

- 캡션: 2,200자 이내
- 첫 줄: 강력한 훅 (피드에서 보이는 영역)
- 줄바꿈과 이모지로 가독성 확보
- CTA: 저장/공유/댓글 유도
- 톤: 친근, 감성적, 공감형
- 필수 구조: 훅 → 본문 → CTA → 해시태그
- 해시태그: 20~30개 (관련성 높은 것 우선)
- 비주얼 제안: 어울리는 이미지/캐러셀 구성 제안

#### 뉴스레터 본문

- 제목(subject line): 50자 이내, 오픈율 높이는 형식
- 프리헤더: 80자 이내
- 본문: 500~800단어
- 구조: 인사 → 핵심 내용 → 추가 자료 → CTA
- 톤: 1:1 대화형, 친밀하면서도 가치 전달
- 필수 구조: 개인적 인사 → 핵심 가치 → 부가 정보 → CTA 버튼 텍스트
- 플랫폼 참고: Substack, 스티비, 메일침프 등에 바로 붙여넣을 수 있는 형태

#### 썸네일/비주얼 가이드

- 썸네일 텍스트: 핵심 문구 (4~8자)
- 색상 제안: 주 색상 + 강조 색상 (HEX 코드 포함)
- 레이아웃: 텍스트 위치, 이미지 구성 설명
- 표정/제스처 제안 (인물 포함 시)
- 대체 시안 2~3개
- 참고: 16:9 비율 기준, 모바일에서도 가독성 확보

#### YouTube Shorts / TikTok 스크립트

- 길이: 30~60초 분량 (150~300자)
- 구조: 훅(3초) → 본론 → 반전/CTA
- 첫 문장: "~하는 방법", "~하지 마세요", 질문형 등 강력한 훅
- 톤: 빠르고 에너지 넘치는 구어체
- 필수 구조: 3초 훅 → 핵심 정보 → 팔로우/구독 CTA
- 자막 텍스트: 화면에 표시할 핵심 텍스트 별도 제공

#### Facebook 게시물

- 본문: 500자 이내
- 이미지/링크 설명 포함
- 공유를 유도하는 구성
- 톤: 커뮤니티형, 대화 유도
- 필수 구조: 훅 → 본문 → 의견 요청형 CTA

#### Pinterest 핀 설명

- 제목: 100자 이내, 키워드 포함
- 설명: 500자 이내
- 보드 제안
- 톤: 실용적, 검색 최적화
- 필수 구조: 키워드 풍부한 설명 + 행동 유도

#### Threads 게시물

- 500자 이내
- 대화형 구성
- 이미지 없이도 임팩트 있는 텍스트
- 톤: 캐주얼, 트렌디, 밈 감성 가능
- 필수 구조: 훅 → 짧은 본문 → 반응 유도

#### 브런치 글

- 제목: 감성적이면서 검색 가능한 형태
- 본문: 2,000~4,000자
- 소제목 활용, 문단 나누기, 인용구 활용
- 톤: 에세이형, 깊이 있는 서술
- 필수 구조: 감성적 도입 → 본론 → 여운 있는 마무리

#### Medium 아티클

- 제목: 영문 기준 60자 이내, 호기심 유발형
- 서브타이틀: 제목 보완, 핵심 가치 제시
- 본문: 1,500~3,000단어 (영문 기준) / 한글 시 2,000~4,000자
- 구조: H2 소제목, 인용 블록, 코드 블록(기술 글), 볼드/이탤릭 적절 활용
- 톤: 전문적이면서 읽기 쉬운 에세이형
- 필수 구조: 훅 도입 → 문제 정의 → 본론 (소제목별) → 결론/CTA
- 태그: 5개 이내 관련 태그 제안

### 4단계: 품질 검증

콘텐츠 생성 후 다음 항목을 자체 검증합니다. 이 단계는 결과물의 품질을 보장하기 위해 중요합니다:

1. **글자 수 확인**: 각 플랫폼의 글자 수 제한을 초과하지 않았는지 확인
   - X 트윗: 140자(한글) / 280자(영문) 이내
   - Instagram 캡션: 2,200자 이내
   - LinkedIn: 1,300자 이내
   - 초과 시 자동으로 수정하여 제한 이내로 맞춤
2. **원본 충실도**: 원본의 핵심 메시지 3가지를 추출하고, 각 플랫폼 결과물에 해당 메시지가 포함되어 있는지 확인
3. **플레이스홀더 확인**: "[여기에 입력]", "[링크]" 등 미완성 요소가 없는지 스캔

### 5단계: 출력

**핵심 원칙: 각 플랫폼 결과물은 사용자가 그대로 복사하여 해당 플랫폼에 붙여넣기만 하면 바로 게시할 수 있는 완성본이어야 합니다.**

아래 출력 규칙을 반드시 따르세요:

1. **플랫폼별로 구분**: `## [플랫폼명]` 헤더 바로 아래에 완성된 콘텐츠를 출력합니다.
2. **복사-붙여넣기 최적화**:
   - "[여기에 입력]", "[링크]", "[이미지]" 같은 플레이스홀더를 절대 사용하지 마세요. 실제 내용으로 채우세요.
   - "톤:", "형식:", "필수 요소:" 같은 메타 레이블을 결과물에 넣지 마세요.
   - 코드 블록(```)으로 콘텐츠를 감싸지 마세요.
   - "아래는 ~입니다", "다음과 같이 작성했습니다" 같은 설명 문구를 콘텐츠 앞뒤에 붙이지 마세요.
3. **플랫폼 네이티브 형식 그대로**:
   - X 스레드: 각 트윗을 번호(1/7, 2/7...)로 구분, 마지막에 해시태그 포함
   - Instagram: 이모지, 줄바꿈, 구분선, 해시태그 모두 포함된 완성본
   - LinkedIn: 줄바꿈, 해시태그 포함된 완성본
   - 블로그: 마크다운 H2/H3, 리스트, 볼드 등 그대로 사용 가능한 형태
   - 뉴스레터: 제목(subject line)과 본문을 명확히 구분
   - 썸네일 가이드: 텍스트, 색상 코드, 레이아웃 설명을 바로 디자이너에게 전달 가능한 형태
4. **SEO 블로그의 경우**: 제목, 메타 디스크립션, 키워드를 본문 상단에 별도 표기한 뒤 본문을 이어서 출력합니다.
5. **마지막에 요약 표**: 모든 플랫폼 콘텐츠 출력이 끝난 후 아래 형식으로 요약합니다.

| 플랫폼 | 글자 수 | 핵심 키워드 | CTA |
|--------|---------|------------|-----|

6. **파일 저장**: 생성된 콘텐츠가 3개 플랫폼 이상이면 마크다운 파일로 저장합니다.
   - 파일명: `repurposed-[주제요약]-[날짜].md` (예: `repurposed-1인개발자수익화-20260407.md`)
   - 저장 위치: workspace 폴더 (Cowork 환경에서 사용자가 접근 가능한 경로)
   - 저장 후 `computer://` 링크로 사용자에게 파일 위치를 안내

## 모드 2: 콘텐츠 감사 (audit)

기존에 발행한 콘텐츠 라이브러리를 체계적으로 분석하여 개선 포인트를 도출하는 모드입니다.

### 정보 수집

사용자에게 다음 정보를 AskUserQuestion으로 수집합니다:

1. **분석 대상**: 콘텐츠 목록 (제목, URL, 주제, 발행일 등)
   - 텍스트로 직접 입력, 파일 첨부(CSV/엑셀), 또는 URL 목록
2. **분석 목적**: 어떤 인사이트를 얻고 싶은지
   - 예: 주제 커버리지 확인, 성과 개선, 콘텐츠 캘린더 수립 등
3. **운영 채널**: 어떤 플랫폼에서 콘텐츠를 운영 중인지

### 분석 프레임워크

다음 5가지 관점에서 체계적으로 분석합니다:

**① 주제 분포 분석**
- 전체 콘텐츠를 주제/카테고리별로 분류
- 각 카테고리의 콘텐츠 수와 비율을 표로 정리
- 특정 주제에 편중되어 있는지, 빠진 주제가 있는지 시각적으로 표현

**② 시의성 분석**
- 발행일 기준으로 최신성 평가 (6개월 이상 된 콘텐츠 표시)
- 업데이트가 필요한 콘텐츠 식별 (변경된 정보, 새로운 트렌드 반영 필요)
- 시즌별/시기별 콘텐츠 발행 패턴 분석

**③ 형식 다양성 분석**
- 텍스트, 영상, 인포그래픽, 리스트형, 튜토리얼 등 형식별 분포
- 부족한 콘텐츠 형식 식별

**④ 중복/통합 기회**
- 주제가 겹치는 콘텐츠를 그룹핑
- 통합하면 더 강력해질 콘텐츠 조합 제안

**⑤ 우선순위 액션 플랜**
- 즉시 실행 (1주 이내): 간단한 업데이트, 오류 수정
- 단기 (1개월): 부족한 주제 보완, 형식 다양화
- 중기 (3개월): 콘텐츠 시리즈 기획, 신규 채널 진출

### 출력 형식

```
# 콘텐츠 감사 리포트

## 1. 요약 (Executive Summary)
- 총 콘텐츠 수, 주요 발견사항 3가지

## 2. 주제 분포
| 카테고리 | 콘텐츠 수 | 비율 | 상태 |
(과잉/적정/부족 표시)

## 3. 시의성 평가
| 콘텐츠 제목 | 발행일 | 업데이트 필요 여부 | 우선순위 |

## 4. 형식 분포
| 형식 | 수량 | 권장 비율 대비 |

## 5. 중복/통합 기회
- 통합 후보 그룹별 정리

## 6. 액션 플랜
| 우선순위 | 액션 | 대상 콘텐츠 | 기대 효과 |
```

결과가 10개 항목을 초과하면 마크다운 파일로 저장합니다.

## 모드 3: 갭 분석 (gap)

경쟁 채널/사이트와 비교하여 콘텐츠 갭을 찾고 전략적 기회를 도출하는 모드입니다.

### 정보 수집

사용자에게 다음 정보를 AskUserQuestion으로 수집합니다:

1. **내 콘텐츠**: 현재 보유한 콘텐츠 목록/주제
   - 직접 입력, 파일 첨부, 또는 채널 URL
2. **경쟁 대상**: 비교하고 싶은 채널/사이트
   - URL을 제공하면 WebSearch를 활용하여 경쟁 채널 콘텐츠를 조사
3. **분석 범위**: 주제, 형식, 플랫폼, 기간 등
4. **목표**: 어떤 갭을 메우고 싶은지 (트래픽 증가, 신규 오디언스 확보 등)

### 분석 프레임워크

**① 주제 갭 분석**
- 경쟁 채널이 다루지만 우리가 다루지 않는 주제 목록
- 각 주제의 예상 검색량/관심도 표시 (가능한 경우)
- WebSearch로 해당 주제의 트렌드 확인

**② 형식 갭 분석**
- 경쟁 채널의 콘텐츠 형식 분포 vs 우리의 형식 분포
- 우리가 시도하지 않은 형식 (예: 인포그래픽, 팟캐스트, 쇼츠 등)

**③ 플랫폼 갭 분석**
- 경쟁 채널이 활동하는 플랫폼 vs 우리가 활동하는 플랫폼
- 진출하지 않은 플랫폼의 기회와 비용 평가

**④ 빈도/일관성 갭**
- 발행 빈도 비교
- 시리즈/연재물 유무 비교

### 출력 형식

```
# 콘텐츠 갭 분석 리포트

## 1. 요약
- 가장 큰 갭 3가지, 즉시 실행 가능한 기회

## 2. 주제 갭
| 주제 | 경쟁 채널 보유 | 우리 보유 | 기회 크기 | 난이도 |
(기회 크기: 상/중/하, 난이도: 상/중/하)

## 3. 형식 갭
| 형식 | 경쟁 | 우리 | 권장 사항 |

## 4. 플랫폼 갭
| 플랫폼 | 경쟁 활동 여부 | 우리 활동 여부 | 진출 권장도 |

## 5. 콘텐츠 로드맵
| 주차 | 주제 | 형식 | 플랫폼 | 비고 |
(4주 분량의 구체적 실행 계획)
```

경쟁사 URL이 제공된 경우, WebSearch를 활용하여 공개된 콘텐츠 정보를 수집합니다. 단, 사용자에게 "검색 결과를 기반으로 분석하므로 실제 성과 데이터와 차이가 있을 수 있다"는 점을 안내합니다.

결과가 상세할 경우 마크다운 파일로 저장합니다.

## 대화 흐름 규칙

1. **정보가 부족하면 반드시 질문**: 원본 콘텐츠, 분야, 톤 등 필수 정보가 없으면 생성하지 말고 AskUserQuestion으로 질문합니다.
2. **출력 언어**: 기본값은 한국어입니다. 사용자가 다른 언어를 요청하면 해당 언어로 작성합니다.
3. **플랫폼 선택은 사용자에게 위임**: 임의로 모든 플랫폼을 생성하지 않습니다.
4. **원본 충실도**: 원본의 핵심 메시지와 논점을 왜곡하지 않습니다.
5. **플랫폼 특성 준수**: 각 플랫폼의 글자 수 제한, 톤, 형식을 반드시 따릅니다.
6. **즉시 게시 가능한 완성본**: 모든 결과물은 해당 플랫폼에 그대로 복사-붙여넣기하면 바로 게시할 수 있는 형태로 작성합니다. 플레이스홀더, 메타 설명, 불필요한 안내 문구를 절대 포함하지 마세요.
7. **파일 저장**: 3개 이상 플랫폼 결과물이나 감사/갭 분석 리포트는 마크다운 파일로 저장하고 사용자에게 링크를 제공합니다.
