## 7.4.2 감사 모드 실행하기

첫 번째 실습에서는 원본 콘텐츠 1개를 넣어서 여러 플랫폼용 콘텐츠를 만들었습니다. 방향이 "1 → N"이었습니다. 두 번째 실습에서는 반대입니다. 기존 콘텐츠 여러 개를 넣어서 분석 리포트 1개를 받습니다. 방향이 "N → 1"입니다. 같은 스킬인데, 변환 모드는 확산이고 감사 모드는 수렴입니다.

Cowork 입력창에 다음과 같이 입력합니다.

> 기존에 쓴 블로그 글들을 점검해줘. 어떤 주제가 부족한지 알고 싶어.

전송 버튼을 누르면 클로드가 content-repurpose 스킬을 인식하되, 이번에는 변환 모드가 아니라 **감사 모드**로 진입합니다. 7.3.1에서 "콘텐츠 리퍼포징 해줘"라고 했을 때 변환 모드가 자동으로 실행됐던 것과 같은 원리입니다. 차이점은, "점검", "감사", "audit" 같은 키워드가 들어가면 클로드가 감사 모드로 분기한다는 것입니다. SKILL.md 안에 이런 규칙이 적혀 있기 때문입니다.

[그림 7-12] "기존에 쓴 블로그 글들을 점검해줘" 입력 후 클로드가 감사 모드로 진입하는 화면

감사 모드에 들어가면 클로드가 세 가지를 물어봅니다. 4장에서 회의록 만들기 전에 역할, 용도, 출력 형식을 물어봤던 것, 6장에서 리서치 전에 관심 분야와 용도를 물어봤던 것과 같은 패턴입니다.

> 콘텐츠 감사를 도와드리겠습니다. 다음 정보가 필요합니다.
>
> 1. **분석 대상**: 기존 콘텐츠 목록을 공유해 주세요 (제목, URL, 주제, 발행일 등 — 텍스트, CSV/엑셀 파일, URL 목록 모두 가능)
> 2. **분석 목적**: 어떤 인사이트를 얻고 싶으신가요?
> 3. **운영 채널**: 어떤 플랫폼에서 콘텐츠를 운영 중이신가요?

[그림 7-13] 감사 모드에서 클로드가 세 가지 정보를 요청하는 화면

왜 이 세 가지를 물어볼까요? 각각의 역할이 다릅니다.

**분석 대상**은 감사의 범위를 정합니다. 콘텐츠가 10개인지 100개인지에 따라 분석의 깊이가 달라지고, 제목만 있는지 URL까지 있는지에 따라 클로드가 할 수 있는 일의 범위가 달라집니다.

**분석 목적**은 감사의 방향을 정합니다. "부족한 주제를 찾고 싶다"와 "오래된 글을 업데이트하고 싶다"는 같은 콘텐츠 목록으로도 완전히 다른 분석 결과를 만들어냅니다. 병원에 가서 "전체 건강검진 해주세요"와 "허리가 아파서 왔어요"가 다른 검사를 하는 것과 비슷합니다.

**운영 채널**은 맞춤형 제안을 하기 위한 것입니다. 블로그만 운영하는 사람에게 "Instagram에 이런 콘텐츠를 올리세요"라고 하면 쓸모가 없습니다. 반대로 유튜브와 블로그를 함께 운영하는 사람이라면 "이 블로그 글은 영상으로 만들면 더 효과적입니다" 같은 크로스 플랫폼 제안이 가능합니다.

변환 모드에서 "분야/톤"과 "플랫폼 선택"을 물어봤던 것과 비교해보면, 목적은 같습니다. **클로드가 정확한 결과를 내기 위해 필요한 맥락을 먼저 수집하는 것입니다.** 2장부터 반복해서 확인해온 패턴입니다. 잘 만든 스킬은 무조건 작업을 시작하지 않고, 필요한 정보를 먼저 질문합니다.

## 7.4.4 감사 결과 살펴보기

분석이 끝나면 클로드가 다섯 가지 관점에서 정리한 감사 리포트를 보여줍니다. 7.3.2에서 네 개 플랫폼 결과물을 하나씩 살펴봤던 것처럼, 이번에도 하나씩 뜯어보겠습니다.

### 7.4.4.1 주제 분포 분석

첫 번째는 **주제 분포 분석**입니다. 전체 콘텐츠를 카테고리별로 분류하고, 각 카테고리의 비율과 상태(과잉/적정/부족)를 표로 정리합니다.

| **카테고리** | **콘텐츠 수** | **비율** | **상태** |
|---|---|---|---|
| Fine-Tuning (LLM/VLM/RL/STT/TTS) | ~20+ | 35% | **과잉** |
| LLM API 사용법 (Claude/OpenAI/Google) | ~12 | 20% | 적정 |
| 블로그/뉴스 (AI Weekly, 에세이) | ~10 | 17% | 적정 |
| 기초이론 (BM25, Batch Norm 등) | 3 | 5% | **부족** |
| RAG | 2 | 3% | **심각하게 부족** |
| Agent | 1 | 2% | **심각하게 부족** |
| LangGraph | 1 | 2% | **심각하게 부족** |
| 프롬프트 엔지니어링 | 0 | 0% | **부재** |
| 평가/벤치마크 | 0 | 0% | **부재** |

한눈에 보이는 것이 있습니다. **Fine-Tuning이 전체의 35%를 차지하며 심하게 편중**되어 있습니다. 특히 TTS Fine-Tuning 하나만 Qwen3-TTS 관련 글이 7개 이상입니다. 하나의 세부 주제에 콘텐츠가 과도하게 집중된 것입니다.

그런데 더 눈에 띄는 것은 반대편입니다. 이 책의 제목은 "LLM부터 **Agent까지**"입니다. 그런데 **Agent에 해당하는 콘텐츠가 단 1개**("Agent란 무엇인가?")뿐입니다. RAG도 2개, LangGraph도 1개에 불과합니다. 책의 제목이 약속한 것과 실제 콘텐츠 사이에 큰 간극이 있는 셈입니다.

여기서 핵심 포인트를 확인할 수 있습니다. 클로드가 **우리가 적은 카테고리만 분석한 것이 아니라, 이 분야에서 있어야 할 카테고리까지 스스로 추론해서 추가했다**는 점입니다. 우리는 URL만 던졌을 뿐인데, 클로드가 "LLM 학습 자료라면 프롬프트 엔지니어링, 평가/벤치마크, MLOps 같은 주제도 있어야 한다"고 판단해서 빈 영역을 찾아낸 것입니다. 감사 모드가 단순한 분류가 아니라 **빈 곳을 찾아내는 진단**인 이유가 여기 있습니다.

이 분석을 사람이 직접 하려면 수십 개 페이지를 하나씩 읽고 카테고리를 분류해야 합니다. 10개라면 10분이면 될 수 있지만, 이 책처럼 60개 이상의 페이지가 있으면 반나절이 걸립니다. 클로드는 이 작업을 1~2분 만에 끝냅니다.

이번 실습에서는 기술 블로그를 대상으로 감사를 돌렸지만, 감사 모드는 콘텐츠가 쌓이는 곳이라면 어디든 적용할 수 있습니다. 예를 들어 뷰티 유튜버라면 "리뷰 영상이 70%인데 튜토리얼은 하나도 없다"는 편중을 발견할 수 있고, 사내 교육 담당자라면 "신입 온보딩 자료는 10개인데 중간 관리자용 리더십 교육은 0개"라는 갭이 드러날 수 있습니다. 프리랜서 디자이너가 포트폴리오 사이트를 점검하면 "웹 디자인 작업만 8개이고 브랜딩이나 UX 프로젝트는 비어 있다"는 진단이 나올 수 있고, 부동산 블로거라면 "아파트 분양 분석은 매주 올리면서 전세·월세 실전 가이드는 한 편도 없다"는 걸 알게 됩니다. 핵심은 **자기가 만든 콘텐츠 안에서는 빈 곳이 잘 보이지 않는다**는 것입니다. 매일 글을 쓰는 사람일수록 자기가 자주 다루는 주제에 익숙해져서, 다루지 않는 영역을 의식하지 못합니다. 감사 모드는 그 사각지대를 대신 찾아줍니다. 블로그든, 유튜브든, 사내 위키든, 포트폴리오든 — 여러분이 콘텐츠를 쌓아가고 있는 곳이라면 지금 바로 한번 돌려보세요. URL 하나만 넘기면 됩니다.

### 7.4.4.2 시의성과 중복 분석

두 번째는 **시의성 평가**입니다. 콘텐츠가 얼마나 오래되었는지, 업데이트가 필요한 콘텐츠는 무엇인지 보여줍니다.

클로드가 업데이트 우선순위 TOP 3을 이렇게 꼽았습니다.

**1위: Claude Code 관련 글들.** Claude Code는 2026년 들어 플러그인, Cowork 모드 등 대폭 변화가 있었습니다. 현재 글이 이 기능들을 반영하고 있는지 점검이 필요합니다.

**2위: OpenAI 사용법.** GPT-4o 이후 o3, o4-mini 등 새 모델이 대거 등장했는데, 기존 글이 이를 반영하지 못하고 있을 가능성이 높습니다.

**3위: AI Weekly News 시리즈.** 2025년 11~12월에 작성된 주차별 뉴스인데, 6개월이 지난 뉴스 콘텐츠는 개별 방문 동기가 거의 없습니다.

여기서 클로드가 **콘텐츠의 분야 특성을 고려한다**는 점이 중요합니다. AI 분야의 글이 6개월~1년만 지나도 업데이트가 필요하다고 판단한 반면, BM25 알고리즘 같은 기초 이론 글은 "시의성과 무관, 업데이트 필요 낮음"으로 분류했습니다. 단순히 날짜만 보는 것이 아니라, 해당 분야의 변화 속도까지 고려해서 판단하는 것입니다.

세 번째는 **중복/통합 기회**입니다. 클로드가 네 가지 통합 대상을 찾아냈습니다.

| **통합 대상** | **현재 상태** | **통합 제안** |
|---|---|---|
| AI News 시리즈 (4개) | 주차별로 분산 | "2025년 4분기 AI 핵심 뉴스 모아보기" 1개로 통합 |
| Qwen3-TTS 시리즈 (7개+) | single/multi-speaker 등 세분화 | "Qwen3-TTS Fine-Tuning 완전 가이드" 1~2개로 통합 |
| Claude Code 하위 글 (5개+) | 기본, 모드, 서브에이전트 분산 | 허브 페이지를 만들어 전체 흐름을 잡아주기 |
| 크롤링 도구 (2개) | Firecrawl, Travily 별도 글 | "크롤링 도구 비교" 1개로 통합 |

특히 Qwen3-TTS 시리즈가 눈에 띕니다. 7개 이상의 글이 single speaker, multi-speaker, instruct 모드 등으로 나뉘어 있는데, 유사한 내용이 반복되고 있습니다. 이것을 하나의 "완전 가이드"로 통합하고 단계별(입문→고급)로 재구성하면 독자 입장에서 훨씬 따라가기 쉬워집니다. 3장에서 엑셀의 여러 탭을 하나로 취합했던 것처럼, 흩어진 콘텐츠를 하나로 모으는 것입니다.

### 7.4.4.3 콘텐츠 갭과 액션 플랜

네 번째는 **콘텐츠 갭 분석**입니다. 7.4.4.1에서 Agent, RAG, 프롬프트 엔지니어링이 부족하다는 것을 발견했는데, 여기서는 그 빈 영역을 **구체적인 콘텐츠 제안**으로 채워줍니다.

클로드가 이 책의 구조("LLM → Fine-Tuning → RAG → Agent"라는 파이프라인)를 파악한 뒤, 파이프라인의 빈 곳을 짚어줍니다. 단순히 "이 영역이 부족합니다"에서 끝나지 않고, "이런 글을 쓰면 됩니다"까지 알려주는 것입니다.

예를 들어 Agent 챕터에 대해서는 이런 제안이 나옵니다. "현재 'Agent란 무엇인가?' 1개뿐이므로, Agent 아키텍처(ReAct, Plan-and-Execute, Tool Use), LangGraph 기반 Agent 구축 실습, 멀티 에이전트 시스템 입문, Agent 실전 프로젝트(예: 리서치 에이전트 만들기)를 추가하세요."

다섯 번째이자 마지막은 **우선순위 액션 플랜**입니다. 지금까지의 분석을 종합해서, 실제로 무엇부터 해야 하는지를 시간 순서로 정리합니다.

**즉시 실행(1~2주):** Agent 챕터를 "Agent란 무엇인가?" 1개에서 최소 5개로 확장합니다. 책 제목이 "LLM부터 Agent까지"인데 Agent 콘텐츠가 1개뿐이라는 것은 가장 시급한 문제입니다. 동시에, Claude Code와 OpenAI 관련 글이 2026년 최신 기능을 반영하고 있는지 점검합니다.

**단기(1개월):** RAG 파이프라인 시리즈를 현재 2개에서 최소 7개로 확장합니다. RAG 개념 입문, 청킹 전략, 임베딩 모델 비교, 벡터 DB 비교, 성능 최적화까지. 그리고 프롬프트 엔지니어링 섹션을 새로 만들어 기초 원칙, 고급 기법, 실전 템플릿 모음 3개를 추가합니다.

**중기(3개월):** 평가/벤치마크 섹션을 신설합니다. 그리고 AI News 주차별 글들을 월별 또는 분기별로 통합하고, Qwen3-TTS 시리즈 7개 이상의 글을 "완전 가이드" 1~2개로 재구성합니다.

여기서 핵심은 이 액션 플랜이 **앞의 네 가지 분석(주제 분포, 시의성, 중복, 갭)을 종합한 결과**라는 점입니다. "즉시 실행"의 Agent 확장은 갭 분석에서, Claude Code 업데이트는 시의성 평가에서 나온 것입니다. "중기"의 TTS 통합은 중복 분석에서 나온 것입니다. 개별 분석 결과를 나열하는 데 그치지 않고, 실행 가능한 계획으로 묶어주는 것입니다.

6장에서 content-research 스킬이 콘텐츠 캘린더를 만들어줬던 것과 비교해보면 역할이 다릅니다. 캘린더가 "앞으로 새로 만들 것"에 초점을 맞추는 반면, 감사 모드의 액션 플랜은 "이미 만든 것을 어떻게 개선하고, 그 위에 무엇을 더할 것인가"에 초점을 맞춥니다. 두 가지를 함께 쓰면 더 효과적입니다. 감사 모드로 빈 영역을 찾아낸 다음, 그 결과를 6장의 content-research 스킬에 넣어서 "RAG 관련 콘텐츠 아이디어를 찾아줘"라고 하면, 빈 영역을 채울 구체적인 아이디어까지 한 번에 나옵니다. **이전 장에서 배운 스킬과 이번 장의 스킬을 연결해서 쓰는 것, 이것이 스킬을 하나씩 쌓아가는 진짜 효과입니다.**
