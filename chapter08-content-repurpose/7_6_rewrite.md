## 7.6 이 장을 마치며

이번 장에서는 하나의 콘텐츠를 여러 플랫폼에 맞게 자동 변환하는 방법을 배웠습니다. 첫 번째 실습에서 유튜브 영상 하나로 SEO 블로그, X 스레드, LinkedIn 게시물, 뉴스레터를 한 번에 만들어봤고, 두 번째 실습에서는 위키독스 URL 하나만 던져서 60개 이상의 콘텐츠를 체계적으로 점검하는 감사 모드를 경험했습니다.

이 장에서 확인한 핵심 원칙은 두 가지입니다.

첫째, **같은 팩트라도 플랫폼이라는 맥락에 따라 완전히 다른 형태의 콘텐츠가 만들어진다.** 2장부터 반복해서 경험해온 "맥락을 줄수록 결과물이 달라진다"는 원칙의 연장선입니다. 4장에서는 역할과 용도가 맥락이었고, 6장에서는 분야와 콘텐츠 용도가 맥락이었습니다. 이번 장에서는 **플랫폼**이 맥락입니다. content-repurpose 스킬의 SKILL.md에는 14개 플랫폼 각각의 규칙이 구체적으로 적혀 있고, 클로드는 그 규칙을 따라 결과물의 형태를 바꿉니다.

둘째, **같은 스킬이라도 방향을 바꾸면 완전히 다른 일을 한다.** 변환 모드는 1개를 넣어서 여러 개를 만드는 확산(1→N)이었고, 감사 모드는 여러 개를 넣어서 1개의 분석 리포트를 받는 수렴(N→1)이었습니다. 감사 모드에서 클로드가 "책 제목이 'Agent까지'인데 Agent 콘텐츠가 2%뿐이다"라고 짚어낸 장면을 기억하시나요? 우리가 입력하지 않은 카테고리까지 추론해서 빈 곳을 찾아내는 것, 이것이 단순한 분류와 진단의 차이입니다.

그리고 스킬의 구조 면에서도 중요한 발견이 있었습니다. content-repurpose 스킬은 **SKILL.md 하나로 모든 것을 처리합니다.** 파이썬 파일이 하나도 없습니다. 글쓰기와 형태 변환이 핵심 작업이기 때문에, 별도의 프로그래밍 도구 없이 지침만으로 충분합니다. 모든 스킬에 복잡한 코드가 필요한 것은 아니라는 것, 이것은 나중에 여러분이 스킬을 직접 만들 때 기억해두면 좋은 포인트입니다.

잠깐 지금까지의 여정을 돌아보겠습니다.

| **장** | **자동화한 것** | **입력** | **출력** |
|---|---|---|---|
| 2장 | 문서·PPT 만들기 | PDF, URL, 기업 정보 | PPT, 보고서 |
| 3장 | 엑셀 정리·분석 | 엑셀 파일 | 정리된 데이터, 차트 |
| 4장 | 회의록 정리 | 음성 파일, 텍스트 | 회의록 |
| 5장 | 스킬 개선·커스터마이징 | 기존 스킬 | 개선된 스킬 |
| 6장 | 콘텐츠 아이디어 찾기 | 키워드 한 줄 | 아이디어 리스트, 캘린더 |
| **7장** | **콘텐츠 대량 생산 + 점검** | **유튜브 링크, 위키독스 URL** | **4개 플랫폼 완성본 + 감사 리포트** |

2장에서는 파일을 넣어서 파일을 받았습니다. 6장에서는 키워드 한 줄만 넣어도 리서치 결과가 나왔습니다. 이번 장에서는 링크 하나로 여러 플랫폼의 콘텐츠가 동시에 나오고, URL 하나로 수십 개 콘텐츠의 진단 리포트가 나왔습니다. **입력은 점점 단순해지는데, 출력은 점점 다양해지고 있습니다.** 이것이 스킬을 활용하는 자동화의 방향입니다.

6장에서 "뭘 만들지"를 자동화하고, 7장에서 "만든 걸 어떻게 퍼뜨릴지"를 자동화했습니다. 감사 모드로 "지금까지 만든 것을 어떻게 개선할지"까지 자동화했습니다. **만들고 → 퍼뜨리고 → 점검하는 콘텐츠의 전체 라이프사이클**을 하나의 스킬로 관리할 수 있게 된 셈입니다.

다음 장에서는 텍스트를 다루는 것에서 영상을 다루는 것으로 넘어갑니다. 유튜브 롱폼 영상 하나에서 쇼츠 10개를 자동으로 뽑아내는 실습을 해보겠습니다. 자동화의 범위가 한 단계 더 넓어집니다.
